# 02: 新 cfg 格式、轉移舊 cfg，偵測螢幕並擷取成「預設」模式

**What to build:** 程式能用 Windows 顯示設定 API 偵測目前接上的每台螢幕（廠牌、型號、序號、接孔、目前狀態、支援的解析度與更新率），並以「廠牌 + 型號 + 序號」辨識螢幕，讀不到序號時改用「廠牌 + 型號 + 接孔」（ADR-0003）。cfg 改為 INI 分段格式，存放一般設定、模式與每個模式的螢幕設定，程式整份重寫並附中文註解。第一次以新版啟動時，若讀到舊格式 cfg，先備份為 `.bak`，轉移仍有意義的值（自動切換、滑鼠移動門檻、聲音音量門檻、聲音持續秒數、忽略遠端輸入、通知），捨棄其餘；開機啟動狀態從登錄檔沿用。cfg 不存在或為舊格式時，以擷取目前螢幕狀態建立「預設」模式。工作列選單新增「將目前螢幕狀態存入〈目前模式〉…」，確認後擷取並存檔。此階段切換仍沿用舊有方式，尚不依模式套用。

## Comments

### 2026-11-20 實作完成（待手動實測）

- 核心新增：`Monitors.cs`（`MonitorId`、`DetectedMonitor`、`MonitorSettings`、`ModeConfig`、`VideoMode`、`Orientation`）、`Capture.cs`（擷取規則）；`ConfigFile.cs` 改為 INI 分段格式（`[General]`、`[Mode.N]`、`[Mode.N.Monitor.K]`），整份重寫並附中文註解。新 port `IMonitorSystem.Detect()`；`IConfigStore` 新增 `CreateBackup()`。
- 螢幕識別文字形式：`廠牌/型號/SN:序號`，讀不到序號時為 `廠牌/型號/PORT:接孔`（接孔 = 輸出類型 + 接孔編號，例如 `DP1`、`HDMI2`）。萬一兩台沒有序號的同型號螢幕接孔名稱相同（兩張顯示卡各一個 DP1、DP 串接），轉接層會在接孔後加上目標 ID 區分。
- Windows 轉接層 `WindowsMonitorSystem`：QueryDisplayConfig（QDC_ALL_PATHS）列出接上的螢幕，EDID 從登錄檔讀取廠牌/型號/序號，EnumDisplaySettings 取目前狀態與支援的顯示模式，DisplayConfig 的建議模式作為原生解析度。已在開發機實測偵測到 3 台螢幕（其中 1 台 EDID 無序號，改用接孔）。
- **與規格的刻意差異（過渡期）**：規格說轉移時捨棄 `BatPath`、`HomeArgs`、`AwayArgs`、`IdleMinutes`、`AudioDetect`、`LastMode`，但本票「切換仍沿用舊有方式」需要這些值，因此暫時保留在 `[LegacySwitch]` 分段（從舊 cfg 轉移過來）。**票 03 應移除 bat 相關鍵，票 04 應移除其餘並刪除整個分段與 `Mode` 列舉。**
- 寫入策略改為整份重寫（舊版只改單一鍵、保留使用者未重新載入的修改，這個行為依規格取消）。cfg 讀取失敗或舊版備份失敗時，本次執行不寫入 cfg，避免覆蓋原檔，並在啟動通知中說明。
- 舊格式判定比規格寬鬆：只要「沒有分段且有內容」就視為舊格式（先備份再轉換），不要求含舊鍵名，避免無分段的檔案未經備份就被覆蓋。
- 開機啟動：轉移與首次建立時從登錄檔讀入 `StartWithWindows`；工作列切換開機啟動時一併寫入 cfg。每次啟動依 cfg 同步登錄檔留給票 05。
- 已知限制：關閉中的螢幕只能取得原生解析度，`SupportedModes` 只有這一筆（票 08 選單若需要完整清單再補）；複製（鏡像）模式下兩台都會被判為主螢幕。
- 59 個測試全部通過；在暫存資料夾以實際舊 cfg 試跑 exe，`.bak` 與原檔逐位元組相同，轉出的新 cfg 內容正確。
- 尚未完成：手動實測（同型號螢幕、換接孔時識別結果符合 ADR-0003），以及工作列「將目前螢幕狀態存入「預設」…」的確認視窗操作。
