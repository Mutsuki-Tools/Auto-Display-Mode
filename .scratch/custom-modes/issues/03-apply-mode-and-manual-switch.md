# 03: 用 Windows API 套用模式，從工作列手動切換任何模式

**What to build:** 程式改用 Windows 顯示設定 API 套用模式的螢幕設定（ADR-0002），不再需要 bat 與 MultiMonitorTool（從工作目錄移除）。工作列選單列出所有模式，目前模式打勾、切換中顯示提示，點一下即手動切換。套用規則：模式中記錄但沒接上的螢幕略過；接上但未記錄的螢幕依該模式的「未記錄的螢幕：維持現狀/關閉」設定（預設維持現狀）；若結果沒有任何螢幕開著則拒絕套用並通知。套用失敗時維持原本的模式、跳出錯誤通知、自動切換暫停 1 分鐘。每個模式有「手動切換進入此模式時，自動切換要維持/開啟/關閉」設定（預設維持）與工作列圖示顏色；圖示以目前模式的顏色繪製，實心表示自動切換開、空心表示關。切換進行中再次手動切換時提示「正在切換中」。

## Comments

### 2026-11-21 實作完成（待手動實測）

- 核心新增 `ApplyPlanner.cs`（套用規劃）。協調者改為：手動切換任何模式（`ManualSwitch(modeId)`），先偵測螢幕、規劃，再透過 `IMonitorSystem.BeginApply` 在背景套用；目前模式要等套用成功（`OnSwitchFinished(null)`）才改變並存檔。`IDisplaySwitcher` 整個移除（只剩 bat 用途）；套用加在既有的 port `IMonitorSystem` 上。
- 套用規劃的主螢幕規則：以模式中第一台「開啟且標記為主螢幕」的為準；它沒接上或被關閉時，改用模式中第一台開啟的螢幕，再沒有就用第一台維持開啟的未記錄螢幕；整體平移座標讓主螢幕位於 (0,0)。維持現狀的未記錄螢幕不搶主螢幕，座標沿用它目前的座標（可能與模式中的螢幕重疊，重疊檢查留給票 05／08 的配置驗證）。
- 每個模式新增 cfg 鍵：`Color=#RRGGBB`、`ManualAutoSwitch=Keep|On|Off`、`UnlistedMonitors=Keep|Off`（預設都是 Keep）。cfg 中沒寫顏色的模式會依調色盤配上第一個沒被使用的顏色，因為工作列圖示需要每個模式都有顏色（故事 10 的「新增模式時自動配色」之後由設定視窗沿用同一個函式）。
- 套用失敗：維持原模式、錯誤通知、自動切換暫停 1 分鐘，閒置計時不歸零（暫停結束後條件仍成立就再試一次）。偵測失敗與「沒有任何螢幕會開著」的拒絕也一樣暫停 1 分鐘，避免自動切換每秒重試、一直跳通知（規格只寫「套用失敗」，這裡刻意擴大到這兩種情況）。手動切換的維持/開啟/關閉只在套用成功時才生效。自動切換的通知改在套用成功後才跳出。
- Windows 轉接層 `WindowsMonitorSystem.BeginApply`：在背景執行緒（1）開啟中的螢幕與要求不同時，以 `SetDisplayConfig`（`SDC_USE_SUPPLIED_DISPLAY_CONFIG | SDC_ALLOW_CHANGES | SDC_SAVE_TO_DATABASE`）開關螢幕：保留要的開啟中路徑，新開啟的螢幕各選一個沒被使用的顯示來源，模式交給系統選；（2）等新螢幕就緒（最多約 3 秒），再以 `ChangeDisplaySettingsEx`（`CDS_UPDATEREGISTRY | CDS_NORESET`，主螢幕加 `CDS_SET_PRIMARY` 並先設定）暫存每台的解析度、更新率、方向、座標，最後一次套用。中途失敗且螢幕已被改動時，會盡量還原為切換前的狀態（同時蓋掉已暫存在登錄檔的設定），錯誤通知中會說明是否還原成功。
- 方向：偵測與套用共用同一張 DMDO 對照表（`DMDO_90` = Portrait），因此「擷取後再套用」一定還原成相同的方向；`Portrait` 這個標籤是否等於 Windows 設定裡的「直向」仍待直向螢幕實測。
- 工作列：選單列出所有模式（顏色方塊 + 名稱），目前模式打勾，切換中的目標模式後面加「（切換中…）」，狀態列顯示「正在切換到「X」…」；圖示用目前模式的顏色繪製，實心 = 自動切換開、空心 = 關。舊的「切換成遊玩/省電模式」三個選項移除。
- 已從工作目錄移除 `monitormode.bat`、`monitormode_backup.bat`、`MultiMonitorTool.exe/.chm/.cfg`、`readme.txt`（MultiMonitorTool 的說明）以及 `BatDisplaySwitcher.cs`。
- 82 個測試全部通過（新增 `ApplyTests`，並把切換相關的舊測試改成兩個模式 + `HomeMode`／`AwayMode` 的新格式）。

#### 過渡決定：舊的兩條切換條件怎麼對應到模式

- `[LegacySwitch]` 新增 `HomeMode`、`AwayMode`（模式 ID，0 = 沒有），表示舊的兩條切換條件中扮演「遊玩」與「省電」的模式：處於 `HomeMode` 且閒置 `IdleMinutes` 分鐘 → 切到 `AwayMode`；處於 `AwayMode` 且偵測到實體滑鼠使用（或持續播放聲音）→ 切到 `HomeMode`。兩者都指向存在且不同的模式時才作用；處於其他模式時不自動切換，也不掛滑鼠鉤子。
- 這樣「目前模式」只剩 `CurrentMode` 一個來源，舊的遊玩/省電狀態由 `CurrentMode` 加上這兩個鍵推導，不會出現兩份狀態不一致。`Mode` 列舉保留，用來表示這兩個角色。
- **與票 02 交代的差異**：`LastMode` 不再寫出，只在讀取時用來轉移：cfg 沒有 `HomeMode`／`AwayMode` 時，把目前模式設為 `LastMode` 對應的角色（當時擷取的「預設」就是那個狀態）。保留寫出 `LastMode` 會變成與 `CurrentMode` 重複、可能互相矛盾的狀態，所以提早移除寫出；讀取的轉移程式碼與 `IdleMinutes`、`AudioDetect`、`Mode` 列舉一起留到票 04 刪除。
- **升級後的影響**：票 02 的 cfg 只有一個「預設」模式，升級後只會設定其中一個角色（使用者目前的 cfg 為 `LastMode=home` → `HomeMode=1, AwayMode=0`），所以自動切換暫時不作用，直到新增第二個模式並填上另一個鍵。啟動通知與說明會顯示「舊版切換條件未設定」。
- `bat` 相關的 `BatPath`、`HomeArgs`、`AwayArgs` 已移除：讀到時忽略，下次存檔就不再出現。

#### 手動實測步驟

1. 執行 `build.bat` 後啟動新的 exe。cfg 會被改寫：`[LegacySwitch]` 只剩 `HomeMode=1`、`AwayMode=0`、`IdleMinutes`、`AudioDetect`，`[Mode.1]` 多出 `Color`、`ManualAutoSwitch`、`UnlistedMonitors`。
2. 從右鍵選單「以文字文件開啟cfg檔」，在檔尾加上：
   ```
   [Mode.2]
   Name=省電
   ```
   並把 `[LegacySwitch]` 的 `AwayMode=0` 改成 `AwayMode=2`，存檔後選「重新載入cfg檔」。選單應出現「預設」（打勾）與「省電」兩個模式，各有不同顏色的方塊。
3. 點「省電」：此時「省電」沒有記錄任何螢幕，所有螢幕維持現狀（畫面不變），切換完成後「省電」打勾、圖示變成「省電」的顏色。
4. 到 Windows 顯示設定把螢幕調成想要的省電配置（例如只留 MSI、2560x1440 60Hz），再從選單選「將目前螢幕狀態存入「省電」…」→「是」。
5. 點「預設」：三台螢幕應恢復原本的配置（開關、解析度、更新率、座標、主螢幕）。再點「省電」：應變回步驟 4 的配置。切換中打開選單應看到「（切換中…）」；切換中再點一次應跳出「正在切換中，請稍候。」。
6. 自動切換：在「預設」閒置 `IdleMinutes` 分鐘應自動切到「省電」並跳出通知；在「省電」動一下實體滑鼠應切回「預設」。從選單關閉自動切換後，圖示應變成空心。
7. 手動切換的自動切換設定：在 cfg 把「省電」加上 `ManualAutoSwitch=Off`、重新載入，手動切到「省電」後自動切換應變成關（空心圖示）。
8. 拔掉一台螢幕（例如 Wacom）後在兩個模式間切換：其餘螢幕照常套用，不會出錯。
9. 直向螢幕：在 Windows 設定把某台螢幕設為「直向」後擷取存入某模式，確認 cfg 中該螢幕的 `Orientation` 為 `Portrait`；切到別的模式再切回來，方向應正確還原。
