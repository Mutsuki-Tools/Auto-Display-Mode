# 05: 設定視窗骨架與一般設定

**What to build:** 雙擊工作列圖示或從選單選「設定…」開啟設定視窗（只允許開一個）。視窗底部有「確定/取消/套用」：修改先暫存在視窗內，按套用或確定才寫入 cfg，取消則放棄。設定視窗開著時暫停自動切換，工作列的「重新載入 cfg」暫時停用。本票建立「一般設定」分頁：滑鼠移動門檻、聲音音量門檻、聲音持續秒數、忽略遠端輸入、自動切換通知、開機登入時自動開啟。開機啟動以 cfg 為準，程式每次啟動時將登錄檔 Run 機碼同步為 cfg 的值與目前 exe 路徑（不需系統管理員權限）。工作列選單整理為最終內容（目前模式、各模式、自動切換、設定…、存入目前模式…、用記事本開啟 cfg、重新載入 cfg、說明、關閉程式），並更新說明內容，介面文字一律使用 `GLOSSARY.md` 的用語。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 設定視窗可從雙擊圖示與選單開啟，再次開啟時帶到前景而非開第二個
- [ ] 一般設定各欄位修改後按套用即寫入 cfg 並立即生效；按取消不改變任何東西
- [ ] 設定視窗開著時不發生自動切換，且「重新載入 cfg」停用
- [ ] 開機啟動勾選與 cfg、登錄檔一致；exe 搬家後重開程式，登錄檔路徑自動更新
- [x] 測試涵蓋：設定視窗開啟時暫停自動切換、開機啟動依 cfg 同步、一般設定儲存後讀回相同

## Comments

### 2026-11-21 實作完成（待手動實測）

#### 設定視窗的資料流（票 06～08 沿用）

- 開啟視窗時以 `AppConfig.Clone()` 深複製一份副本（`ModeConfig.Clone()` 連螢幕設定清單一起複製；`SwitchCondition`、`MonitorSettings` 是不可變的 record，複製清單即可）。各分頁直接修改這份副本。
- 分頁繼承 `Settings/SettingsPage`：`OnLoad(draft)` 顯示副本內容，控制項改變時寫回副本並呼叫 `MarkEdited()`（啟用「套用」），`CommitEdits()` 在套用前確認還沒送出的輸入（例如數字欄位中剛打的字）。新分頁只要加進 `SettingsForm` 的 `pages` 陣列。
- 「套用」／「確定」呼叫協調者的 `ApplySettings(draft)`：先驗證（`AppConfig.Validate`：一般設定範圍、目前模式存在、每條切換條件有效），再寫入 cfg，成功後才換成新設定並立即生效（重算鉤子需求、聲音持續秒數歸零）。失敗時回傳原因，設定維持不變；視窗跳出訊息並保留修改。cfg 讀取失敗（或舊版備份失敗）而不能寫入時，也回傳原因，不會當成成功。
- **目前模式與自動切換以協調者記錄的為準**：套用時忽略副本中的 `CurrentModeId` 與 `AutoSwitch`。自動切換不在一般設定分頁中，只能從工作列開關。
- 給票 06：擷取後「存入的模式隨即成為目前模式並重新計時」需要擴充 `ApplySettings`（例如多一個「套用後成為目前模式的模式 ID」參數）；`Validate` 目前只檢查「目前模式存在」，票 06 的刪除規則可以加在這裡。

#### 設定視窗開著時

- 協調者新增 `OnSettingsWindowOpened`／`OnSettingsWindowClosed` 與 `SettingsWindowOpen`。開著時 `Tick` 不切換，鉤子也移除（`ApplyHookPolicy` 多一個條件）。
- **關閉時所有閒置計時歸零，並有 3 秒緩衝期**（與手動開關自動切換相同）。理由：編輯期間沒播放聲音時，「只選聲音」的閒置條件會一直累積，關閉視窗當下就會切換；緩衝期避免按「確定」的那一下被重新安裝的鉤子當成使用。
- `ReloadConfig` 在協調者中拒絕並通知（選單也停用）。
- **工作列的手動切換、開關自動切換仍可使用**：只改變目前模式與自動切換，套用時不會被副本蓋掉。
- **工作列的擷取停用**（協調者也拒絕）：規格只要求停用「重新載入 cfg」。擷取會改變目前模式的螢幕設定，但副本裡沒有這次擷取的結果，之後按套用就會蓋掉。在設定視窗中擷取是票 06 的功能。

#### 開機啟動

- 以 cfg 為準：每次啟動與重新載入 cfg 時，都依 `StartWithWindows` 呼叫 `IStartupRegistration.SetEnabled`。開啟時寫入目前的 exe 路徑（已存在也覆寫），關閉時刪除；失敗時附加在啟動或重新載入的通知中。在設定視窗變更時才同步，失敗時跳出錯誤通知；cfg 仍會寫入，下次啟動再試一次。重新載入時也同步是規格外的決定，理由同樣是以 cfg 為準。
- cfg 讀取失敗時不同步（設定是預設值，同步可能誤刪開機啟動）。這時視窗中的勾選顯示的是預設值，不一定與登錄檔相同，但套用會被拒絕，不會造成損害。舊版轉移時如果 .bak 備份失敗，同樣不同步，要等下次能正常寫入 cfg 時才會更新 exe 路徑。
- `RegistryStartup.IsEnabled` 改為只要有本程式的 Run 值就算開啟，不比對路徑。現在只有首次啟動與轉移舊格式時會讀它（使用者故事 81），所以 exe 搬家後第一次啟動仍沿用開機啟動，並立即同步成新路徑。
- 移除協調者的 `ToggleStartup`、`StartupEnabled` 與工作列的開機啟動選單項目。

#### 一般設定的範圍

- 範圍定義在 `AppConfig` 的常數上，設定視窗的欄位、`AppConfig.ValidateGeneral` 與讀取 cfg 時的 `ConfigFile.Normalize` 共用：滑鼠移動門檻 1～1000 像素、聲音音量門檻 0～1、聲音持續秒數 1～3600 秒。
- 讀取時超出範圍：滑鼠移動門檻夾到範圍內；聲音持續秒數小於 1 用預設的 3（沿用舊行為）、大於 3600 用 3600；聲音音量門檻超出範圍或不是數字時用預設的 0.005。cfg 的註解也加上範圍。

#### 工作列選單與說明

- 選單：目前模式、各模式、自動切換（打勾表示開）、設定…（粗體，雙擊圖示的預設動作）、將目前螢幕狀態存入「X」…、用記事本開啟 cfg、重新載入 cfg、說明、關閉程式。
- 雙擊圖示開啟設定視窗；已經開著時還原（如果最小化）並帶到前景。關閉程式時直接關閉設定視窗（放棄未套用的修改）。
- 說明改寫：「當前為」改為「目前」；「模式目前只能在cfg檔中新增與修改」改為「模式目前請用記事本開啟 cfg 新增與修改」；切換條件也一樣。這兩句在票 06、07 完成後要再改寫。新增【一般設定】段落與「設定視窗開著時暫停自動切換」。cfg 的開頭註解改為「重新載入 cfg」。

#### 高 DPI

- 新增 `app.manifest`，宣告**系統 DPI 感知**（`<dpiAware>true</dpiAware>`），設定視窗以 `AutoScaleMode.Dpi` 依系統 DPI 放大，選單的顏色方塊也依 DPI 放大。在主螢幕的縮放比例（4K、150%）下清楚；移到縮放比例不同的螢幕時，由 Windows 點陣縮放。
- 沒有用每台螢幕各自感知（PerMonitorV2）：.NET Framework 4.8 的 WinForms 需要另附 exe.config 才能在螢幕間重新縮放，會破壞單一 exe 的產出（ADR-0001）。
- 目前 cfg 中的座標（例如副螢幕 X=-2560）已是實體像素，推測顯示設定 API 不受 DPI 虛擬化影響，但**必須手動實測擷取與套用**（步驟 9）。

#### 審查後的修正

- 存檔前的驗證從協調者搬到 `AppConfig.Validate`；註解中的「螢幕配置」（詞彙表要避免的用語）改掉；測試只透過協調者斷言。
- 判斷題，沒有修改：範圍檢查在 `ValidateGeneral` 與 `Normalize` 各寫一次；新增一般設定要改多處（`Clone`、cfg 讀寫、分頁、說明）；錯誤通知沿用「設定檔」，選單與說明用「cfg」。
- 另外注意：詞彙表把「螢幕配置」列為要避免的用語，但 spec 與票 08 把分頁叫「螢幕配置」，票 08 開始前要決定用語。

137 個測試全部通過（新增 `SettingsWindowTests`，`ConfigTests` 改為開機啟動同步與範圍正規化）。

#### 手動實測步驟

1. 先從工作列關閉正在執行的舊版程式，再執行 `build.bat`，然後啟動新的 exe。
2. 右鍵選單依序為：目前模式、各模式、自動切換（打勾）、**設定…**、將目前螢幕狀態存入「X」…、用記事本開啟 cfg、重新載入 cfg、說明、關閉程式。沒有開機啟動的選單項目。
3. 雙擊工作列圖示開啟設定視窗；再雙擊一次或從選單選「設定…」，不會開第二個視窗。把視窗最小化後再雙擊圖示，應還原並帶到前景。
4. 視窗在 4K、150% 的螢幕上文字清楚，不模糊；版面沒有被切掉。
5. 設定視窗開著時：右鍵選單的「重新載入 cfg」與「將目前螢幕狀態存入…」為灰色；可以從選單手動切換模式。把 `[Switch.1]` 改成閒置 1 分鐘（用記事本改後先關閉設定視窗再重新載入，再開設定視窗），開著設定視窗不碰滑鼠鍵盤超過 1 分鐘，不應自動切換；關閉視窗後再閒置 1 分鐘，才切換。在「省電」中開著設定視窗動滑鼠，也不應切回。
6. 在一般設定把滑鼠移動門檻改為 20、聲音持續秒數改為 5、取消勾選「自動切換時跳出通知」，按「套用」：「套用」變成灰色、視窗不關閉；用記事本開啟 cfg，應看到 `MouseMoveThreshold=20`、`AudioSeconds=5`、`ShowNotifications=0`。之後自動切換時不跳通知。再改回原值，按「確定」：視窗關閉，cfg 改回。
7. 修改幾個欄位後按「取消」（或按 Esc、或關閉視窗）：cfg 不變，重新開啟設定視窗時顯示原本的值。
8. 開機啟動：勾選「開機登入時自動開啟」並套用，cfg 為 `StartWithWindows=1`，登錄檔 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 有 `AutoDisplayMode`，值為目前 exe 的路徑；取消勾選並套用，該值消失。再勾選後關閉程式，把 exe（連同 cfg）複製到別的資料夾執行，登錄檔的路徑應更新為新的位置。測完刪除複製出來的資料夾，並從原本的位置啟動一次，讓路徑改回來。
9. DPI 感知後的擷取與套用：從選單手動切換「預設」與「省電」，每台螢幕的開關、解析度、座標應與切換前（舊版）相同；從選單擷取目前模式後，cfg 中的座標與解析度應與 Windows 顯示設定一致（例如 4K 螢幕 3840x2160、副螢幕 X=-2560），且與擷取前相同。
10. 說明視窗沒有「當前為」，有【一般設定】段落。
11. 把 `[Switch.1]` 的 `IdleTime` 改回原值並重新載入。
