# 06: 模式分頁

**What to build:** 設定視窗新增「模式」分頁，使用者可新增、刪除、重新命名、複製模式。名稱不可空白或重複；新增模式自動配一個未使用的顏色。刪除模式前跳確認，列出會一併刪除的切換條件（來源或目標是該模式者）；最後一個模式與目前模式不可刪除。重新命名不影響切換條件。每個模式可設定圖示顏色、「手動切換進入此模式時，自動切換要維持/開啟/關閉」、「未記錄的螢幕：維持現狀/關閉」。提供「以目前螢幕狀態覆蓋此模式」與「以目前螢幕狀態新增模式」，結果先暫存，按套用/確定才存檔；存入的模式隨即成為目前模式並重新計時。

**Blocked by:** 03, 04, 05

**Status:** ready-for-agent

- [x] 刪除確認會列出連帶刪除的切換條件；最後一個與目前模式無法刪除且說明原因
- [x] 擷取到非目前模式並套用後，目前模式改為該模式，工作列圖示隨之更新
- [x] 測試涵蓋：刪除時連帶刪除切換條件、最後一個與目前模式不可刪、名稱不可空白/重複、重新命名不影響條件、複製產生獨立的螢幕設定、擷取後目前模式變更與計時歸零

## Comments

### 2026-11-21 實作完成（待手動實測）

#### 模式管理（在副本上操作，票 07、08 可沿用）

- `AppConfig` 新增：`NextModeId()`（目前最大 ID + 1）、`AddMode()`（名稱「新模式」「新模式 2」…、配未使用的顏色）、`DuplicateMode(id)`、`UniqueModeName()`、`ConditionsReferencing(id)`、`RemoveMode(id)`（連帶刪除來源或目標是該模式的切換條件，回傳被刪的條件）、`ModeRemovalBlocker(id, 目前模式)`、`ValidateModeName(id, 名稱)`。
- `ModeConfig.CopyAs(id, 名稱)`：以新 ID 深複製；`Clone()` 改為呼叫它（保留 ID）。首次啟動建立「預設」模式也改用 `NextModeId()`。
- 名稱規則：去掉前後空白後不可空白；與其他模式比較時去掉前後空白、不分大小寫。套用時把名稱前後的空白去掉再存檔。
- `AppConfig.Validate` 依序加上：至少要保留一個模式、每個模式名稱有效（不可空白／重複）、目前模式存在。**注意**：手動編輯 cfg 造成名稱重複時，套用任何設定（包括一般設定）都會被擋下並說明原因，要先在模式分頁改名。
- 複製模式：名稱「X 的複本」（重複時加編號）、配一個未使用的顏色（方便在工作列分辨），手動切換時的自動切換、未記錄的螢幕、螢幕設定都與原模式相同（清單各自獨立）。**切換條件不複製**（規格沒有要求，複製後可能與原模式的條件重複觸發）。
- 刪除最大 ID 的模式後再新增，新模式會沿用那個 ID：被刪模式的切換條件已一併刪除，副本中不會有指向它的東西。

#### 視窗內擷取與 `ApplySettings`

- 協調者新增 `CaptureForSettings(既有螢幕設定)`：偵測並回傳 `Capture.Run` 的結果，不存檔、不改變目前模式。切換中或偵測失敗時通知（與 `CaptureToCurrentMode` 相同的文字）並回傳 null。工作列的擷取在設定視窗開著時仍然停用。
- `ApplySettings(draft, capturedModeId = null)`：`capturedModeId` 是視窗中最後一次擷取存入的模式。套用成功後它成為目前模式，所有閒置計時歸零（與工作列擷取相同）。以下情況忽略它，目前模式仍以協調者為準：
  - 沒有擷取（null）。
  - **擷取的模式在套用前被刪除**：視窗也會清掉記錄；目前模式不變，擷取結果隨模式一起刪除。
  - **擷取了多個模式**：只有最後一次擷取的模式成為目前模式（它代表最新的螢幕狀態）；先前擷取的模式仍存入擷取結果，但不成為目前模式。
  - **擷取之後又切換過螢幕**（從工作列手動切換，成功或失敗都算）：擷取的結果已不代表目前的螢幕狀態，所以不改變目前模式；擷取的螢幕設定仍會存入。
- `Validate` 以「套用後的目前模式」檢查，所以擷取到 A 並套用時，原本的目前模式可以被刪除（介面上仍以協調者的即時值擋下刪除目前模式）。
- **切換中拒絕套用**（「正在切換中，請稍候再套用。」，視窗保留修改）：切換完成時會改變目前模式，與擷取或刪除模式同時發生時結果難以預期。切換通常只有幾秒。

#### 介面

- 新增 `Settings/ModesPage`，排在一般設定之前（分頁順序依規格：模式、螢幕配置、切換條件、一般設定）。左邊為模式清單（顏色方塊、目前模式標示「（目前）」）與「新增／複製／刪除」「以目前螢幕狀態新增模式」；右邊為名稱（即時顯示空白／重複的錯誤）、圖示顏色（8 個預設色與「其他…」）、手動切換進入此模式時的自動切換、未記錄的螢幕、螢幕設定摘要與「以目前螢幕狀態覆蓋此模式」。
- 刪除：最後一個模式與目前模式（讀 `app.Config.CurrentModeId` 的即時值）按下時以訊息視窗說明原因；可刪除時跳確認，列出會一併刪除的切換條件（`SwitchCondition.Describe`）。
- 覆蓋此模式前跳確認；以目前螢幕狀態新增模式不確認（新增的模式可直接刪除）。擷取後在模式下方顯示「已擷取目前螢幕狀態（尚未存檔）」；擷取多個模式時每個都會顯示。
- 分頁訂閱 `app.Changed`：設定視窗開著時從工作列手動切換，清單的「（目前）」即時更新。
- **給票 07**：`SettingsForm` 在切換分頁時對該分頁重新呼叫 `Load(draft)`，分頁可據此重建下拉選單，反映模式分頁的新增、刪除、改名（`ModesPage` 重新載入時保留選取的模式）。`SettingsPage` 新增 `OnApplied()`，套用成功後呼叫。
- 設定視窗預設大小改為 640x580（96 DPI），模式分頁不需捲動。
- 高 DPI 的坑：**不要在 `Resize` 中設定標籤的 `MaximumSize`**。設定視窗依 DPI 縮放時會觸發 `Resize`，改 `MaximumSize` 會讓縮放重跑，150% 時邊距被放大成 3 倍多。說明文字放在單欄表格中就會自動換行（與一般設定相同）。另外直接放進表格的固定寬度欄位（TextBox）在表格尚未有寬度時會被壓成 1 像素且不會恢復，所以名稱欄位與下拉選單外包一層自動大小的 `FlowLayoutPanel`；也不要用 `MinimumSize` 解決，它在 DPI 縮放時會被放大兩次。
- 說明文字的【模式】改為設定視窗的操作方式；【擷取】加上模式分頁的擷取與「存入的模式隨即成為目前模式」。切換條件那句留給票 07。

157 個測試全部通過（新增 `ModesTabTests` 20 個）。另以拋棄式小程式檢查 96／144 DPI 的版面，並模擬按鈕操作（新增、改名、重複名稱提示、複製、切換分頁、套用寫入 cfg）。

#### 審查後的修正

- 擷取多個模式時，每個擷取過的模式都顯示「已擷取」標示（原本只有最後一個），補上「擷取多個模式」的測試。
- 一般設定與模式分頁重複的粗體標題程式碼抽到 `SettingsPage.BoldLabel`（票 07、08 可沿用）。
- 判斷題，沒有修改：
  - 「擷取之後又切換過螢幕時，擷取的模式不成為目前模式」（`captureStale`）是規格沒有明說的例外，審查認為與「存入的模式隨即成為目前模式」有出入。保留的理由：切換後實際的螢幕狀態是切換到的模式，若仍把擷取的模式設為目前模式，程式記錄的模式會與實際狀態不一致（違反使用者故事 65 的精神）。如果偏好照字面處理，只要移除這個條件。
  - 切換中拒絕套用（包括只改一般設定）、手動編輯造成名稱重複時擋下所有套用、複製時配新顏色、視窗加大，見上方說明。
  - 測試中直接斷言 `ModeRemovalBlocker`／`ValidateModeName` 的回傳值：它們是分頁顯示原因的來源，套用時的阻擋另有透過 `ApplySettings` 的斷言。
  - 「去掉前後空白」分散在名稱檢查與套用兩處、顏色以 `int` 表示、清單繪製的固定像素間距。

#### 手動實測步驟

1. 先從工作列關閉正在執行的舊版程式，再執行 `build.bat`，然後啟動新的 exe。**建議先備份 `AutoDisplayMode.cfg`**（測試會新增、刪除模式）。
2. 開啟設定視窗：第一個分頁是「模式」，清單顯示所有模式與顏色方塊，目前模式標示「（目前）」並預先選取。在 4K、150% 的螢幕上文字清楚、版面沒有被切掉、不需要捲動。
3. 按「新增」：清單多出「新模式」（顏色與其他模式不同），名稱欄位已選取可直接打字。改名為「閱讀」，按「套用」：右鍵選單出現「閱讀」與它的顏色方塊。
4. 名稱：把「閱讀」改成空白或與其他模式相同（例如「省電」），名稱下方立即出現紅字；此時按「套用」跳出「無法套用設定」並說明原因，視窗保留修改。改回「閱讀」。
5. 選「閱讀」按「複製」：出現「閱讀 的複本」，顏色不同，其餘設定相同。
6. 重新命名：把「省電」改名為「睡覺」並套用，右鍵選單顯示「睡覺」；說明視窗中的切換條件顯示「睡覺」，自動切換行為不變。改回「省電」。
7. 刪除：選目前模式按「刪除」，說明「不能刪除目前模式」。選「省電」（有切換條件的模式）按「刪除」，確認視窗列出來源或目標是「省電」的切換條件；按「否」不刪除。刪除「閱讀 的複本」並套用，右鍵選單中消失。
8. 只剩一個模式時按「刪除」，說明「至少要保留一個模式」（可在測試用的 cfg 副本中驗證，或略過）。
9. 圖示顏色、手動切換、未記錄的螢幕：把「閱讀」的顏色改為紫色、手動切換進入時自動切換改為「關閉」並套用；cfg 中 `[Mode.N]` 為 `Color=#9B5AD2`、`ManualAutoSwitch=Off`。從右鍵選單手動切換到「閱讀」：圖示變成紫色空心（自動切換關閉）。
10. 擷取到非目前模式：目前模式為「預設」時，在 Windows 顯示設定調整一下（例如關掉一台螢幕），回到設定視窗選「閱讀」按「以目前螢幕狀態覆蓋此模式」，確認後出現「已擷取目前螢幕狀態（尚未存檔）」；此時 cfg 尚未改變。按「套用」：右鍵選單的目前模式變成「閱讀」，圖示顏色隨之改變；cfg 中「閱讀」的螢幕設定與 Windows 顯示設定一致。
11. 按「以目前螢幕狀態新增模式」：出現新模式，螢幕設定摘要列出目前接上的螢幕；按「取消」關閉視窗，cfg 與工作列都不變。
12. 擷取後從工作列手動切換：擷取到某個非目前模式後先不要套用，從右鍵選單手動切換到另一個模式，再按「套用」：目前模式維持手動切換後的模式，擷取的螢幕設定仍存入。
13. 設定視窗開著時，從右鍵選單手動切換模式，模式分頁的「（目前）」標示即時移動；目前模式無法刪除。
14. 說明視窗的【模式】與【擷取】段落已改寫為設定視窗的操作方式。
15. 測完刪除測試用的模式（或還原備份的 cfg），並把 Windows 顯示設定調回原狀，再從工作列手動切換回原本的模式。
