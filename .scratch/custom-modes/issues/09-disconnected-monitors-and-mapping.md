# 09: 未接上的螢幕清單與手動對應

**What to build:** 螢幕配置分頁的畫布旁新增「未接上的螢幕」清單，列出目前編輯的模式中記錄過、但現在沒接上的螢幕。每一項可「刪除」該筆螢幕設定，或「對應到…」一台目前接上但此模式未設定的螢幕，讓換上同型號新螢幕時能沿用舊設定（ADR-0003）。畫布上標示「此模式未設定」的接上螢幕。

**Blocked by:** 08

**Status:** ready-for-agent

- [x] 拔掉一台螢幕後開啟設定視窗，它出現在「未接上的螢幕」清單中
- [x] 刪除後該筆螢幕設定從模式中移除
- [x] 「對應到…」後，舊螢幕設定改套用到選定的新螢幕，原記錄移除
- [x] 此模式未設定的接上螢幕在畫布上有明顯標示
- [x] 測試涵蓋：對應後螢幕設定轉移到新識別、刪除未接上螢幕的螢幕設定

## Comments

### 2026-11-21 實作完成（待手動實測）

#### 核心（`Core/Monitors.cs`、`Core/Layout.cs`）

- `ModeConfig` 新增：
  - `Disconnected(接上的螢幕)`：此模式記錄、但沒接上的螢幕設定，依記錄的順序。
  - `Unrecorded(接上的螢幕)`：接上、但此模式沒記錄的螢幕。它們是畫布上「此模式未設定」的螢幕，也是「對應到…」的選項。
  - `Records(螢幕識別)`：此模式有沒有這台螢幕的螢幕設定。
  - `RemoveMonitor(螢幕識別)`：刪除螢幕設定。
  - `MapMonitor(舊識別, 新螢幕)`：設定內容與在清單中的位置都不變，只把 Id 與 Name 換成新螢幕的，所以原記錄就此移除。新螢幕必須是此模式沒記錄的，舊識別必須有記錄，否則丟出 `InvalidOperationException`（介面只提供合法的選項）。
- **主螢幕規則**：刪除、對應、`UpdateMonitor` 最後都經過同一段 `KeepPrimaryAtOrigin`，所以規則一致：主螢幕只有一台，而且是開啟的；沒有時由第一台開啟的螢幕接任；平移到 (0,0)；關閉的螢幕取消主螢幕標記。
  - 刪除主螢幕時由第一台開啟的螢幕接任。
  - 對應時，如果舊記錄是主螢幕，新螢幕就成為主螢幕。
  - cfg 中「關閉、但殘留 Primary=1」的螢幕，經過這三種操作都會清掉標記。原本只有 `UpdateMonitor` 會清。
- `MonitorLayout.Check(模式, 接上的螢幕)`：有傳入接上的螢幕時，訊息中沒接上的螢幕名稱後面加「（未接上）」，例如「「主」與「舊螢幕（未接上）」重疊」。`AppConfig.Validate` 不知道接上了哪些螢幕，所以按「套用」被擋下時的訊息沒有這個標示；分頁上的紅字有。
- `MonitorLayout.Overlapping(模式)`：記錄、開啟、而且與其他螢幕重疊的螢幕，與 `Check` 的重疊錯誤一致。清單用它標出【重疊】。`Overlaps` 維持 internal。

#### 介面（`Settings/LayoutPage`、`Settings/LayoutCanvas`）

- **畫布**：`LayoutCanvas.Item` 多帶 `Unrecorded`。此模式未設定的接上螢幕以橘色虛線框與淡橘底色標示，狀態列顯示「此模式未設定」（關閉時是「此模式未設定（關閉）」）。狀態只佔一列，小矩形中才不會被切掉。未接上的螢幕不畫進畫布。
- **欄位**：選取此模式未設定的螢幕時，顯示橘色說明「此模式未設定這台螢幕，套用時依「未記錄的螢幕」維持現狀或關閉；修改設定後就會加入此模式。」
- **未接上的螢幕清單**：放在畫布下方新增的一列（root 第 2 列），按鈕「刪除」「對應到…」在右欄。沒有未接上的螢幕時整列隱藏，不佔畫布的高度。
  - 原本試過放在右欄欄位下方，但 150% 時要捲動才看得到，所以改放畫布下方。`spec.md` 的描述同步改寫。
  - 清單固定約三列高。`Dock = Fill` 時表格會用清單偏好的高度，把畫布擠小。
- **清單項目**：名稱加上序號或接孔，例如「XV272U KV（序號 OLD0001）」。換上同型號新螢幕時名稱相同，要靠這個分辨；對應選單的項目也一樣。造成重疊的項目前面加「【重疊】」，關閉的後面加「（關閉）」。
- **對應到…**：在按鈕下方跳出選單，列出接上、但此模式未設定的螢幕；沒有這種螢幕時按鈕停用。選了之後畫布改為選取新螢幕。按下選單項目時會再檢查一次舊記錄與新螢幕是否仍然有效，因為選單開著時可能插拔了螢幕。
- **偵測失敗時**：不列出清單，`Check` 也不傳接上的螢幕。否則每一台都會被當成沒接上，可能誤刪。
- 說明視窗的【螢幕配置】段落新增兩行（此模式未設定的標示、未接上的螢幕清單）。
- `GLOSSARY.md` 新增「未記錄的螢幕」「未接上的螢幕」「對應」，並區分三者。

#### 測試與檢查

- 新增 `DisconnectedMonitorsTests`（6 個），共 214 個測試全部通過：
  - 清單與對應選項。
  - 刪除未接上的螢幕。
  - 刪除的是主螢幕時由其他螢幕接任，殘留的主螢幕標記也清掉。
  - 對應後螢幕設定轉移到新識別，再切換到此模式時依沿用的設定套用。
  - 對應的舊記錄是主螢幕。
  - 未接上的螢幕造成重疊時，分頁標出「（未接上）」與【重疊】，刪除後即可套用。
- 以拋棄式小程式在 150% 下開啟真正的設定視窗檢查，結果都正確，版面沒有被切掉。小程式使用真實偵測、記憶體中的 cfg，不寫檔、不套用螢幕。情境是在「主螢幕+畫畫」把 XV272U 的記錄換成一台沒接上的同型號舊螢幕，並與主螢幕重疊：
  - 畫布上接上的 XV272U 標示「此模式未設定（關閉）」。
  - 清單列出「【重疊】XV272U KV（序號 OLD0001）」，紅字是「「MAG 322URDF」與「XV272U KV（未接上）」重疊」。
  - 「對應到…」選單只有接上的 XV272U。對應後清單消失，XV272U 沿用舊座標。
  - 再加一筆關閉的舊記錄後按「刪除」，記錄移除；這時沒有可對應的螢幕，「對應到…」停用。

#### 審查後的修正

- 偵測失敗時隱藏清單（見上方）。
- 對應選單按下時重新檢查是否仍然有效，並釋放舊的選單項目。
- 刪除與對應也清掉關閉螢幕殘留的主螢幕標記：抽成 `KeepPrimaryAtOrigin`，`UpdateMonitor` 一併簡化。
- 「有沒有記錄」統一用 `ModeConfig.Records`。
- 【重疊】改由核心的 `MonitorLayout.Overlapping` 判斷，介面不再自己算，`Overlaps` 維持 internal。
- 「名稱＋序號」的組字抽成 `WithIdDetail`。
- 新增測試：對應的舊記錄是主螢幕。
- 補上 `GLOSSARY.md` 的三個用語；`spec.md` 改寫清單位置。
- 判斷題，沒有修改：
  - 按「套用」被擋下時的訊息不標「（未接上）」：`Validate` 沒有偵測結果，分頁上的紅字已經標出。
  - 刪除主螢幕時，接任的「第一台開啟的螢幕」可能也是沒接上的。這與 `UpdateMonitor` 關閉主螢幕時的規則相同；需要時可再設別台為主螢幕。
  - 對應時直接沿用舊的解析度與更新率，不檢查新螢幕是否支援：同型號的螢幕支援相同；就算不支援，欄位的下拉選單也會列出記錄的值（票 08 的例外）。
  - 畫布的填色、框線、虛線、狀態各依 `Unrecorded`／`Enabled` 判斷一次，目前還算可讀，沒有收成一處。
  - 清單與對應選項的測試直接斷言 `Disconnected`／`Unrecorded`／`Check` 的回傳值：它們就是分頁顯示的來源，與票 08 的警告測試相同。刪除與對應的結果都有經過 `ApplySettings` 與重新讀取 cfg 的斷言。

#### 手動實測步驟

1. **先備份 `AutoDisplayMode.cfg`**（這是實際在用的設定，測試會刪除與對應螢幕設定）。從工作列關閉正在執行的舊版程式，再執行 `build.bat`，然後啟動新的 exe。
2. 開啟設定視窗的「螢幕配置」分頁：目前三台螢幕都有記錄，畫布下方不會出現「未接上的螢幕」，畫布也沒有橘色框。
3. 此模式未設定：用記事本開啟 cfg，把「全開」中 XV272U 那一段（`[Mode.1.Monitor.3]` 整段）刪掉並存檔，從工作列選「重新載入 cfg」，再開設定視窗。這個模式的 XV272U 以橘色虛線框標示「此模式未設定」；選取它時欄位下方有橘色說明。拖動它或改任何欄位後，橘色標示消失（它加入了此模式）。按「取消」放棄。
4. 未接上的螢幕：拔掉 XV272U（或拔掉線），設定視窗開著時約 1 秒內，記錄 XV272U 的模式畫布下方出現「未接上的螢幕」清單，列出「XV272U KV（序號 …）」；接回後清單消失。
5. 刪除：XV272U 拔掉時，在某個模式選取清單中的 XV272U 按「刪除」，清單消失、「套用」啟用；按「套用」後用記事本確認該模式沒有 XV272U 那一段。主螢幕仍在 (0,0)。
6. 對應到…：沒有第二台同型號螢幕，所以用 cfg 模擬。在 cfg 某個模式把 XV272U 那一段的 `Monitor=ACR/0833/SN:42122003F4203` 改成 `Monitor=ACR/0833/SN:OLD0001`，重新載入。設定視窗中，畫布上的 XV272U 標示「此模式未設定」，清單列出「XV272U KV（序號 OLD0001）」。選取它按「對應到…」，選單列出「XV272U KV（序號 42122003F4203）」；選了之後清單消失，XV272U 回到原本的座標、解析度與開關，橘色標示消失。按「套用」後 cfg 中又是 `SN:42122003F4203`，舊的 `OLD0001` 不見了。
7. 重疊標示：同第 6 步改成 `OLD0001`，並把那一段的 X、Y 改成與 MAG 重疊（例如 `Enabled=1`、`X=-1000`、`Y=0`），重新載入。清單項目前面有【重疊】，紅字是「「MAG 322URDF」與「XV272U KV（未接上）」重疊」；按「套用」被擋下。按「刪除」後紅字消失，可以套用。
8. 說明視窗的【螢幕配置】段落有「此模式未設定」與「未接上的螢幕」兩行。
9. 測完還原備份的 cfg，從工作列選「重新載入 cfg」或重新啟動程式，再手動切換回原本的模式。
