# 自訂模式與設定視窗

Status: ready-for-agent

## Problem Statement

省電螢幕工具目前只認得「遊玩」「省電」兩個固定模式，每台螢幕的開關、解析度、更新率、座標都寫死在 bat 裡，自動切換條件也只有「閒置 N 分鐘切省電、偵測到使用切遊玩」這一組。只要換了螢幕、拔掉一台、想多一種配置，或想調整切換時機，就得手動改 bat 與 cfg，甚至改程式碼重新編譯。程式無法應付使用者不同的環境，也沒有任何可視化的設定介面。

## Solution

把工具改造成可完全自訂的版本：

- 使用者可以在設定視窗中自由新增、刪除、重新命名、複製**模式**。
- 每個模式儲存每台**螢幕**的**螢幕設定**（開關、座標、解析度、更新率、方向、主螢幕）。設定視窗提供類似 Windows 顯示設定的配置畫布，自動偵測目前接上的螢幕，可拖拉、也可手動輸入座標。
- 使用者可以把目前實際的螢幕狀態**擷取**進模式，例如在 Windows 設定裡調整好之後一鍵存入。
- **切換條件**改成一張表：「來源模式 + 條件 → 目標模式」，條件為「閒置 N 分鐘/小時」或「偵測到使用」，使用來源可複選「鍵盤滑鼠」「聲音」。
- 工作列選單可手動切換到任何模式，並保留自動切換總開關。
- 所有設定都存在 cfg（INI 分段格式），包含開機登入時是否自動開啟。
- 程式直接呼叫 Windows 顯示設定 API 偵測與套用螢幕，不再需要 bat 與 MultiMonitorTool。

## User Stories

### 模式管理

1. 作為使用者，我想新增一個模式並為它命名，以便為新的使用情境建立螢幕配置。
2. 作為使用者，我想重新命名模式，以便名稱符合我的用途，且既有的切換條件不受影響。
3. 作為使用者，我想刪除不再使用的模式，以便清單保持簡潔。
4. 作為使用者，我想在刪除模式前看到會一併刪除哪些切換條件，以便避免誤刪重要規則。
5. 作為使用者，我想複製一個現有模式，以便只修改少數設定就得到新模式。
6. 作為使用者，我希望程式阻止我刪除最後一個模式，以便程式永遠有模式可用。
7. 作為使用者，我希望程式阻止我刪除目前所在的模式，以便程式的狀態不會失去依據。
8. 作為使用者，我希望模式名稱不能空白也不能重複，以便在選單與條件表中不會混淆。
9. 作為使用者，我想為每個模式選擇工作列圖示顏色，以便一眼看出目前在哪個模式。
10. 作為使用者，我希望新增模式時自動配一個未被使用的顏色，以便不必每次手動挑選。
11. 作為使用者，我想為每個模式設定「手動切換進入此模式時，自動切換要維持/開啟/關閉」，以便例如手動切到省電時不會一動滑鼠又被切回來。
12. 作為使用者，我想為每個模式設定「未記錄的螢幕要維持現狀或關閉」，預設維持現狀，以便決定新接上的螢幕在套用此模式時如何處理。

### 螢幕設定與配置畫布

13. 作為使用者，我想在設定視窗看到目前接上的所有螢幕，包含目前關閉的螢幕（以灰色顯示），以便知道有哪些螢幕可以設定。
14. 作為使用者，我想為某個模式設定每台螢幕要開啟或關閉，以便例如省電模式只留一台。
15. 作為使用者，我想用拖拉的方式擺放螢幕位置，以便直覺地排出實體桌面的相對位置。
16. 作為使用者，我希望拖拉時螢幕會磁吸貼齊其他螢幕的邊，以便輕鬆排出無縫配置。
17. 作為使用者，我想手動輸入螢幕的座標，以便精確擺放，不受拖拉精度限制。
18. 作為使用者，我希望座標以主螢幕左上角為 (0,0)，以便與 Windows 的座標系一致。
19. 作為使用者，我希望螢幕重疊時無法存檔並看到原因，以便不會存出 Windows 無法套用的配置。
20. 作為使用者，我希望螢幕之間有空隙時看到警告（但仍可存檔），以便知道游標無法跨越空隙。
21. 作為使用者，我想從下拉選單選擇解析度，且只列出該螢幕實際支援的值，以便不會選到不支援的解析度。
22. 作為使用者，我想從下拉選單選擇更新率，且只列出該解析度下支援的值，以便不會選到不支援的更新率。
23. 作為使用者，我想設定螢幕方向（橫向、直向、橫向翻轉、直向翻轉），以便支援直立擺放的螢幕。
24. 作為使用者，我想指定每個模式的主螢幕，以便不同模式可以有不同的主螢幕。
25. 作為使用者，我希望插拔螢幕時，開著的設定視窗會即時更新畫布，以便不必關掉重開。
26. 作為使用者，我想看到「這個模式記錄過但目前沒接上」的螢幕清單，以便知道模式裡還有哪些螢幕設定。
27. 作為使用者，我想刪除某筆未接上螢幕的螢幕設定，以便清掉已經淘汰的螢幕。
28. 作為使用者，我想把一筆未接上螢幕的螢幕設定「對應到」一台目前接上但未設定的螢幕，以便換上同型號新螢幕時沿用舊設定。
29. 作為使用者，我希望同時接兩台同型號螢幕時程式能分辨它們，以便各自有不同的螢幕設定。
30. 作為使用者，我希望同一台螢幕換插到不同接孔後仍被認得，以便不必重新設定。
31. 作為使用者，我希望在設定視窗中看到每個模式「此模式未設定」的螢幕標示，以便發現需要補設定的螢幕。

### 擷取

32. 作為使用者，我想在設定視窗按「以目前螢幕狀態覆蓋此模式」，以便把在 Windows 設定裡調好的配置存進選取的模式。
33. 作為使用者，我想在設定視窗按「以目前螢幕狀態新增模式」，以便從現況快速建立新模式。
34. 作為使用者，我想從工作列選單選「將目前螢幕狀態存入〈目前模式〉…」，以便不開設定視窗也能存檔。
35. 作為使用者，我希望從工作列選單擷取前先跳確認視窗，以便不會誤按就覆蓋模式。
36. 作為使用者，我希望擷取時，接上且開啟的螢幕會記錄開啟、座標、解析度、更新率、方向與主螢幕，以便完整重現目前配置。
37. 作為使用者，我希望擷取時，接上但關閉的螢幕記錄為關閉，並保留模式中原有的解析度與更新率（沒有就用原生解析度），以便日後打開它時有合理的值。
38. 作為使用者，我希望擷取時，模式中記錄過但目前沒接上的螢幕設定保持不變，以便不會因為暫時拔掉螢幕而遺失設定。
39. 作為使用者，我希望在設定視窗擷取的結果要按「套用/確定」才存檔，以便可以反悔。
40. 作為使用者，我希望擷取存入哪個模式，目前模式就變成那個模式，並重新開始計時，以便後續的切換條件從正確的模式出發。

### 切換條件

41. 作為使用者，我想在設定視窗的切換條件分頁中用表格新增一條「來源模式 + 條件 → 目標模式」，以便定義何時自動切換。
42. 作為使用者，我想設定「閒置 N 分鐘」或「閒置 N 小時」的條件，以便離開電腦一段時間後自動切換。
43. 作為使用者，我想設定「偵測到使用」的條件，以便回到電腦前一碰就自動切換。
44. 作為使用者，我想為每條切換條件複選使用來源「鍵盤滑鼠」與「聲音」，以便決定哪些跡象算使用。
45. 作為使用者，我希望「閒置」只在所選來源全部都沒有使用時才成立，以便看影片時不會因為沒碰滑鼠就被切走。
46. 作為使用者，我希望「偵測到使用」在所選來源任一個出現使用時就成立，以便任何跡象都能喚醒。
47. 作為使用者，我想調整切換條件在表格中的順序，以便同一個來源模式有多條條件時，決定誰優先。
48. 作為使用者，我希望同一來源模式的條件由上往下檢查、第一條成立的就執行，以便行為可預期。
49. 作為使用者，我想建立串連的切換條件（例如遊玩 → 省電 → 全關），以便分階段降低耗電。
50. 作為使用者，我希望來源模式與目標模式不能相同，以便不會建立無意義的條件。
51. 作為使用者，我希望每次切換完成後所有閒置計時歸零，並有 10 秒緩衝期，以便螢幕重新排列造成的游標移動不會誤觸發。
52. 作為使用者，我希望通知音這類短暫聲音不算使用（聲音要持續達門檻秒數才算），以便閒置計時不會被一直打斷，偵測到使用也不會被誤觸。

### 自動切換與手動切換

53. 作為使用者，我想從工作列選單看到所有模式，並點一下就手動切換，以便隨時切到想要的配置。
54. 作為使用者，我想在工作列選單看到目前的模式（打勾），以及是否正在切換中，以便掌握狀態。
55. 作為使用者，我想從工作列選單開關自動切換，以便暫時停用所有切換條件。
56. 作為使用者，我希望工作列圖示用目前模式的顏色顯示，實心表示自動切換開、空心表示關，以便一眼看出狀態。
57. 作為使用者，我希望自動切換時跳出通知（可在一般設定關閉），以便知道程式剛剛做了什麼。
58. 作為使用者，我希望設定視窗開著時暫停自動切換，以便編輯到一半螢幕不會被切走。
59. 作為遠端連線的使用者，我希望遠端軟體送出的鍵盤滑鼠輸入不算使用（可在一般設定關閉），以便遠端操作時不會被切回耗電的模式。
60. 作為使用者，我希望滑鼠微小位移（低於門檻像素）不算使用，以便桌面震動不會誤觸發。
61. 作為玩家，我希望遊玩模式只設閒置條件時，程式完全不掛鍵盤滑鼠鉤子，以便不影響遊戲輸入延遲。

### 安全與錯誤處理

62. 作為使用者，我希望在設定視窗套用螢幕設定後跳出「要保留這些變更嗎？15 秒後自動還原」，以便畫面黑掉時不必做任何事就能恢復。
63. 作為使用者，我希望套用模式時，若結果會讓沒有任何螢幕開著，程式拒絕套用並通知我，以便永遠不會整個黑畫面。
64. 作為使用者，我希望模式中記錄但沒接上的螢幕在套用時被略過，其他螢幕照常套用，以便少一台螢幕也能用。
65. 作為使用者，我希望套用模式失敗時維持原本的模式並收到錯誤通知，以便程式記錄的模式與實際狀態一致。
66. 作為使用者，我希望套用失敗後自動切換暫停 1 分鐘，以便不會每秒重試、一直跳通知。
67. 作為使用者，我希望切換進行中再次手動切換時收到「正在切換中」的提示，以便不會疊加多次切換。

### 設定視窗與 cfg

68. 作為使用者，我想雙擊工作列圖示或從選單選「設定…」開啟設定視窗，以便隨時調整。
69. 作為使用者，我希望設定視窗有「確定/取消/套用」按鈕，修改要按套用或確定才存檔，以便可以放棄修改。
70. 作為使用者，我希望所有設定（模式、螢幕設定、切換條件、一般設定）都存在 cfg 中，以便備份或搬到其他電腦。
71. 作為使用者，我希望 cfg 是 INI 分段格式並附中文註解，以便用記事本也看得懂。
72. 作為使用者，我想從工作列選單用記事本開啟 cfg，以便手動編輯。
73. 作為使用者，我想從工作列選單重新載入 cfg，以便手動編輯後立即生效。
74. 作為使用者，我希望設定視窗開著時「重新載入 cfg」暫時停用，以便兩邊不會互相覆蓋。
75. 作為使用者，我想在一般設定調整滑鼠移動門檻、聲音音量門檻、聲音持續秒數、是否忽略遠端輸入、是否跳出通知，以便適應我的環境。
76. 作為使用者，我想在設定視窗勾選「開機登入時自動開啟」，以便決定程式是否隨 Windows 啟動。
77. 作為使用者，我希望開機啟動的設定以 cfg 為準，程式每次啟動時同步登錄檔，以便 exe 搬家後重開一次程式就修正路徑。
78. 作為使用者，我希望開機啟動不需要系統管理員權限，以便一般帳號也能使用。

### 升級與首次啟動

79. 作為舊版使用者，我希望新版第一次啟動時自動轉移舊 cfg 中仍有意義的值（自動切換、滑鼠門檻、聲音門檻、聲音秒數、忽略遠端輸入、通知），以便不必重新設定。
80. 作為舊版使用者，我希望舊 cfg 在轉換前先備份成 `.bak`，以便出問題時可以還原。
81. 作為舊版使用者，我希望開機啟動狀態從登錄檔讀出並沿用，以便升級後行為不變。
82. 作為首次使用者，我希望程式第一次啟動時用目前螢幕狀態建立一個「預設」模式，以便一開始就有可用的模式。
83. 作為使用者，我希望程式啟動時不會主動套用任何模式，以便登入時不會多閃一次畫面。
84. 作為使用者，我希望程式只允許同時執行一份，再次開啟時提示我到工作列操作，以便不會有兩份程式互相搶著切換。
85. 作為使用者，我想從工作列選單開啟說明，看到目前的設定摘要與操作方式，以便快速了解功能。

## Implementation Decisions

### 建置與執行環境

- 依 ADR-0001：改用 .NET SDK 建置（SDK 風格專案），目標框架 .NET Framework 4.8 + WinForms，使用最新 C# 語法。產出單一 exe，Win10/11 不需另裝 runtime。建置腳本改為呼叫 `dotnet build`／`dotnet test`。
- 依 ADR-0002：移除 bat 與 MultiMonitorTool 依賴，程式直接呼叫 Windows 顯示設定 API（QueryDisplayConfig／SetDisplayConfig 及相關 API）偵測與套用。舊檔案從工作目錄移除，只留在 git 歷史中。
- 新增一個測試專案，目標同為 .NET Framework 4.8。

### 模組劃分（單一接縫：核心 vs Windows 轉接層）

**核心**（不引用任何 Windows API、WinForms 或登錄檔，可完全由測試驅動）：

- **設定模型**：模式、螢幕設定、切換條件、一般設定的資料結構。模式以模式編號識別，名稱可改；切換條件以模式編號指向來源模式與目標模式（編號依模式的順序，套用設定時重新編號，見 ADR-0004）。
- **cfg 編解碼**：INI 分段格式的讀取與寫出（整份重寫並產生中文註解），以及舊格式偵測與轉移。
- **螢幕辨識**：以「廠牌 + 型號 + 序號」組成螢幕識別；讀不到序號時改用「廠牌 + 型號 + 接孔」（ADR-0003）。
- **配置驗證**：檢查螢幕設定是否重疊（錯誤）、是否有空隙（警告）、主螢幕是否唯一且位於 (0,0)、是否至少一台開啟。
- **套用規劃**：輸入「模式」與「目前偵測到的螢幕清單（含支援的顯示模式）」，輸出「要套用的完整螢幕狀態」或「拒絕原因」。規則：記錄但沒接上的螢幕略過；接上但未記錄的螢幕依該模式設定維持現狀或關閉；結果若沒有任何螢幕開著則拒絕。
- **擷取**：輸入「目前螢幕狀態」與「既有模式（可為空）」，輸出新的螢幕設定集合。規則見使用者故事 36–38。
- **切換引擎**：每秒呼叫一次，輸入當下的使用訊號樣本與時間，維護閒置計時、聲音持續計時、緩衝期、失敗後暫停期，輸出「要切換到哪個模式」或「不動作」；同時輸出目前模式需要哪些輸入鉤子。也負責處理手動切換（含模式的「手動切換進入時自動切換維持/開啟/關閉」設定）、擷取後的目前模式變更、設定視窗開啟時的暫停。
- **應用程式協調者**：把上述元件串起來，對外提供單一入口（啟動、每秒 tick、手動切換、擷取、儲存設定、重新載入、切換完成/失敗回報），並透過下列介面與外界互動。

**核心對外的介面（ports）**，由 Windows 轉接層實作、測試以假物件實作：

- **螢幕系統**：列出目前接上的螢幕（識別、目前狀態、支援的解析度/更新率組合）；套用一份完整螢幕狀態並回報成功或失敗。
- **使用訊號**：提供每秒的樣本：自上次樣本以來是否有「鍵盤滑鼠」使用（經門檻與遠端過濾）、Windows 最後輸入時間、聲音峰值。並接受「需要哪些鉤子」的指令。
- **時鐘**：提供單調遞增的毫秒時間。
- **cfg 儲存**：讀取／寫入 cfg 文字，建立 `.bak` 備份。
- **開機啟動**：讀取／設定登錄檔 Run 機碼。
- **通知**：顯示氣球通知。

**Windows 轉接層**（以手動實測驗證）：

- 顯示 API 轉接：偵測螢幕、讀 EDID 廠牌/型號/序號、接孔資訊、列舉支援的顯示模式、套用螢幕狀態、監聽螢幕插拔事件。
- 輸入鉤子：低階滑鼠鉤子（移動門檻、點擊、滾輪、遠端注入過濾）與低階鍵盤鉤子（遠端注入過濾）；只在核心要求時安裝，並定期重新安裝以防被系統移除（沿用現有做法）。
- 聲音峰值：沿用現有 Core Audio 音量表讀取方式。
- 登錄檔 Run 機碼、cfg 檔案存取、氣球通知、單一執行個體檢查。

**介面層（WinForms）**：

- 工作列圖示與右鍵選單（內容見使用者故事 53–56、34、72–73、85）。圖示依模式顏色動態繪製，實心/空心表示自動切換開/關。
- 設定視窗：分頁為「模式」「螢幕配置」「切換條件」「一般設定」；底部「確定/取消/套用」。修改先暫存在視窗內的設定副本，套用時交給協調者儲存。
- 配置畫布：自繪控制項，依比例顯示螢幕矩形，支援拖拉與磁吸、選取後在旁邊欄位編輯數值；右側「未接上的螢幕」清單提供刪除與「對應到…」。
- 套用確認對話框：15 秒倒數，未按保留即還原為套用前的螢幕狀態。

### 切換條件的行為

- 條件類型：「閒置 N（分鐘或小時）」與「偵測到使用」。使用來源：「鍵盤滑鼠」「聲音」，可複選。
- 閒置：所選來源全部都沒有使用持續 N。只選「鍵盤滑鼠」或兩者都選時，滑鼠鍵盤部分以 Windows 最後輸入時間判斷，不需鉤子。
- 偵測到使用：所選來源任一出現使用即成立。含「鍵盤滑鼠」時需要滑鼠與鍵盤鉤子；只有在目前模式為某條此類條件的來源模式時才安裝。
- 聲音必須持續達「聲音持續秒數」（全域，預設 3 秒）且峰值超過音量門檻才算一次使用，適用所有條件。
- 評估順序：只看來源模式等於目前模式的條件，依表格順序，第一條成立者執行。
- 切換後：所有計時歸零；切換執行期間不偵測；完成後 10 秒緩衝期。
- 套用失敗：維持原模式、通知、自動切換暫停 1 分鐘。

### cfg 格式

- 檔名維持 `AutoDisplayMode.cfg`，UTF-8（含 BOM），INI 分段。分段包含：一般設定、每個模式一段、每個模式下每台螢幕一段、每條切換條件一段（以序號表示順序）。
- 程式整份重寫 cfg，並為每段產生中文註解；手動編輯需透過「重新載入」生效。
- 一般設定包含：自動切換、目前模式、滑鼠移動門檻、聲音音量門檻、聲音持續秒數、忽略遠端輸入、自動切換通知、開機登入時自動開啟。
- 舊格式偵測：檔案無分段且含舊鍵名時視為舊格式。轉移 `AutoMode`、`MouseMoveThreshold`、`AudioThreshold`、`AudioSeconds`、`IgnoreRemoteInput`、`ShowNotifications`；捨棄 `BatPath`、`HomeArgs`、`AwayArgs`、`IdleMinutes`、`AudioDetect`、`LastMode`；開機啟動狀態從登錄檔讀取。轉換前備份為 `AutoDisplayMode.cfg.bak`。
- cfg 不存在或為舊格式時，以目前螢幕狀態建立「預設」模式。

### 開機啟動

- 使用目前使用者的登錄檔 Run 機碼（不需系統管理員權限）。cfg 為準，程式每次啟動時將登錄檔同步為 cfg 的值與目前 exe 路徑。

## Testing Decisions

- **好的測試**只驗證核心對外的行為：給定設定、假螢幕清單、假時鐘與使用訊號樣本，斷言協調者輸出的動作（要求套用的螢幕狀態、寫出的 cfg 內容、通知、鉤子需求、目前模式）。不測私有方法或內部資料結構，重構內部時測試不應需要修改。
- **唯一的測試接縫**是「核心 vs Windows 轉接層」：所有自動化測試都透過協調者的入口，搭配螢幕系統、使用訊號、時鐘、cfg 儲存、開機啟動、通知的假物件。
- **要測的行為**：
  - 切換條件：閒置計時（分鐘/小時、多來源「全部沒有」語意）、偵測到使用（多來源「任一」語意）、聲音持續秒數過濾、條件順序優先、串連切換、切換後計時歸零與緩衝期、套用失敗的暫停期、設定視窗開啟時暫停、自動切換關閉時不動作。
  - 手動切換：「維持/開啟/關閉」自動切換的三種模式設定、切換中拒絕重複切換。
  - 鉤子需求：只有目前模式是「偵測到使用 + 鍵盤滑鼠」條件的來源模式時才要求鉤子。
  - 套用規劃：沒接上的螢幕略過、未記錄螢幕維持現狀/關閉、全部關閉時拒絕、主螢幕與座標正確輸出。
  - 擷取：三類螢幕的記錄規則、存入模式後目前模式變更。
  - 配置驗證：重疊為錯誤、空隙為警告、主螢幕位置。
  - 模式管理：刪除時連帶刪除切換條件、最後一個與目前模式不可刪、名稱不可空白/重複、重新命名不影響條件。
  - cfg：寫出再讀回結果相同（round-trip）、舊格式轉移與 `.bak` 備份、首次啟動建立「預設」模式、開機啟動同步。
- **不做自動化測試**（手動實測）：顯示 API 實際套用、EDID 讀取、鉤子、聲音峰值、登錄檔寫入、設定視窗與配置畫布的操作手感、15 秒還原對話框。
- **既有測試**：目前專案沒有任何測試，這是第一個測試專案。測試框架採 xUnit，目標 .NET Framework 4.8。

## Out of Scope

- 縮放比例（DPI %）設定。
- 來源模式選「任何模式」。
- 時段排程、程式執行中、螢幕插拔等其他條件類型。
- 自動判斷目前實際螢幕狀態符合哪個模式（以擷取功能手動處理）。
- 程式啟動時自動套用模式。
- 從舊版 bat 匯入螢幕數值。
