# 票 04 手動實測 SOP

兩個部分：**A. 回到上個配置**（不必關螢幕，先做）、**B. 分層復原**（螢幕會全暗）。每項後面的「預期」對不上時，記下時間與看到的通知。

## 開始前

- release\AutoDisplayMode.exe 要是 2026-11-22 12:00 之後建置的（已包含兩個部分）。之後若重新建置：先從右鍵選單「關閉程式」，再執行 `build.bat`。
- 你的模式：全開、主螢幕+畫畫、單螢幕4k（一般模式），潛行FHD、潛行2K（潛行模式）。兩個潛行模式的內建切換條件都已經是「回到上個配置」。
- 自動切換目前是**關**。測試用的切換條件請勾「強制」，就不必開自動切換。
- 處於潛行模式時，一動**實體**鍵盤滑鼠就會離開（切換完成後有 10 秒緩衝期）。所以 B 部分的做法是：先在 PowerShell 下延遲指令，再從工作列切到潛行模式，**點完選單就雙手離開**，等指令碼時間到嗶一聲自己動作。
- 測試指令碼：在專案資料夾開 PowerShell，執行
  ```powershell
  powershell -ExecutionPolicy Bypass -File .scratch\remote-mode\04-test.ps1 status
  ```
  會列出主程式與守護程式（含父程序），以及 cfg 的 CurrentMode／RestoreMode／PreviousMode。下面用「`04-test.ps1 動作`」簡寫這行指令。
- 有幾項要用 **Chrome 遠端桌面**（手機或另一台電腦）操作：遠端送的輸入不會讓程式離開潛行模式。

## A. 回到上個配置

**A1. 下拉選單與提示**
1. 開設定視窗 →「切換條件」分頁。
2. 預期：
   - 目標模式欄的下拉選單第一個選項是「回到上個配置」，內建切換條件那兩列也有。
   - 文字沒有被截斷。
   - 滑鼠停在目標模式儲存格上，會出現說明提示；表格下方也有一行說明。

**A2. 新增與複製潛行模式的預設值**
1. 「模式」分頁按「新增潛行模式」，再複製「潛行FHD」。
2. 切到「切換條件」分頁。
3. 預期：兩個新的內建切換條件，目標都是「回到上個配置」。
4. 按「取消」，不要套用。

**A3. 從潛行模式回到上個配置**
1. 從工作列手動切到「主螢幕+畫畫」，再切到「潛行FHD」。
2. 等超過 10 秒，動一下滑鼠。
3. 預期：回到「主螢幕+畫畫」（不是順序第一個的「全開」）。

**A4. 從一般模式回到上個配置（中間經過潛行模式不算）**
1. 在「切換條件」分頁新增一條：來源「單螢幕4k」、閒置 1 分鐘、只勾鍵盤滑鼠、目標「回到上個配置」、勾「強制」。按「套用並關閉」。
2. 手動切到「全開」→「單螢幕4k」→「潛行FHD」。
3. 等超過 10 秒動滑鼠，預期回到「單螢幕4k」。
4. 雙手離開 1 分鐘多，預期自動切回「全開」（不是「單螢幕4k」本身）。

**A5. cfg 與重新編號**
1. 右鍵選單「用記事本開啟 cfg」。預期：
   - A4 那條寫成 `To=Previous`。
   - `[General]` 有 `PreviousMode=`（記的是復原模式之前的一般模式）。
2. 在「模式」分頁把「全開」拖到最後，按「套用」。
3. 再開 cfg。預期：
   - `PreviousMode` 的編號跟著「全開」的新編號改了。
   - `To=Previous` 沒變。
4. 把順序改回來。

**A6. 狀態摘要**
1. 切到「單螢幕4k」，右鍵選單「重新載入 cfg」。
2. 預期：通知中 A4 那條寫成「…→ 回到上個配置（強制）」。
3. 測完刪掉 A4 那條切換條件。

## B. 分層復原

每項開始前都在一般模式（例如「全開」）。下面的「切到潛行」是指從工作列點「潛行FHD」，然後雙手離開。

**B1. 從右鍵選單關閉程式**（Chrome 遠端桌面）
1. 遠端連線，切到潛行FHD（實體螢幕全暗）。
2. 從遠端開右鍵選單，按「關閉程式」。
3. 預期：
   - 工作列提示「正在切回復原模式，完成後結束…」，右鍵選單停用。
   - 約 12 秒內實體螢幕恢復成「全開」，程式結束。
   - `04-test.ps1 status`：沒有任何 AutoDisplayMode.exe，CurrentMode 是全開。
4. 重新開啟程式。

**B2. 用工作管理員結束主程式**（Chrome 遠端桌面）
1. 遠端連線，切到潛行FHD。
2. 遠端開工作管理員 →「處理程序」，找到 Auto Display Mode，按「結束工作」。
3. 預期：
   - 約 1～2 秒實體螢幕亮起。
   - 出現第二個工作列圖示（守護程式），通知「Auto Display Mode 意外結束，守護程式已切回復原模式「全開」。」約 5 秒後圖示消失。
   - 守護程式**沒有**被「結束工作」一起結束（有看到上面的通知就是）。
4. `04-test.ps1 status`：CurrentMode 是全開，沒有任何 AutoDisplayMode.exe。
5. 重新開啟程式。

**B3. 主程式被強制結束**（不用遠端，延遲指令）
1. 執行 `04-test.ps1 kill`，20 秒內切到潛行。
2. 預期：嗶聲後約 1～2 秒螢幕亮起，守護程式通知「意外結束…」，指令碼最後顯示的 CurrentMode 是全開。
3. 重新開啟程式（下一項會用到）。

**B4. 守護程式還在復原時重新開啟程式**
1. 執行 `04-test.ps1 kill`，切到潛行。
2. 嗶聲、螢幕亮起後**立刻**雙擊 release\AutoDisplayMode.exe。
3. 預期：
   - 不會跳出「已經在執行中」。
   - 程式等守護程式做完（最多十幾秒）才出現啟動通知。
   - 啟動通知**沒有**「目前模式是潛行模式…改套用復原模式」（因為守護程式已經把 cfg 改好）。

**B5. 主程式卡住 30 秒**
1. 執行 `04-test.ps1 hang`，切到潛行。
2. 預期：
   - 嗶聲（開始卡住）後約 6 秒，守護程式接手：螢幕在十幾秒內亮起，通知「Auto Display Mode 沒有回應，守護程式已切回復原模式「全開」。」
   - 30 秒後第二聲嗶（恢復），主程式通知「Auto Display Mode 有一段時間沒有回應，守護程式已切回復原模式「全開」。」
   - 主程式不會又切回潛行模式。

**B6. 主程式卡住 10 秒**（恢復時守護程式還在套用）
1. 執行下面的指令，切到潛行。
   ```powershell
   powershell -ExecutionPolicy Bypass -File .scratch\remote-mode\04-test.ps1 hang -Seconds 10
   ```
2. 預期：
   - 主程式恢復後等守護程式做完才自己切回，螢幕不會反覆閃爍或切錯。
   - 最後停在全開，有「有一段時間沒有回應」的通知。

**B7. 主程式與守護程式都被結束**（第 3 層：驅動與 Windows）
1. 執行 `04-test.ps1 killall`，切到潛行。
2. 預期：嗶聲後幾秒到十秒內，Windows 自己點亮三台螢幕，排列和解析度記下來是否與「全開」相同。
3. 重新開啟程式。預期：啟動通知寫「目前模式是潛行模式「潛行FHD」，改套用復原模式「全開」」。

**B8. 只結束守護程式**
1. 執行 `04-test.ps1 killguardian`，切到潛行。
2. 嗶聲後**不要動**，等 20 秒。預期：螢幕維持全暗，主程式照常（潛行模式不受影響）。
3. 動滑鼠，預期照常回到全開。

**B9. 登出**
1. 存好其他程式的工作。執行下面的指令，切到潛行。
   ```powershell
   powershell -ExecutionPolicy Bypass -File .scratch\remote-mode\04-test.ps1 logoff -Delay 25
   ```
2. 預期：嗶聲後，實體螢幕在登出畫面結束前就亮起（主程式先切回復原模式）。
3. 重新登入後程式會自動啟動（開機啟動已開）：
   - 成功：啟動通知只有「已啟動／目前：全開」。
   - 失敗：啟動通知出現「目前模式是潛行模式…改套用復原模式」，表示登出時沒來得及切回。

**B10. 重新開機**
1. 存好工作。執行下面的指令，切到潛行。
   ```powershell
   powershell -ExecutionPolicy Bypass -File .scratch\remote-mode\04-test.ps1 reboot -Delay 25
   ```
2. 預期與判斷方式同 B9。
