# 01: 切換條件的「強制」欄位、設定視窗小改進、建置輸出改到 release 資料夾

**What to build:** 切換條件新增「強制」欄位：勾選後，即使自動切換關閉、設定視窗開著，這條也照樣生效（使用者故事 21、22）。同時改進設定視窗：切換條件分頁的「鍵盤滑鼠」與「聲音」兩欄等寬（35）；有未套用的變更時顯示提醒（36），關閉前先確認（37）。另外，之後執行檔會帶著驅動檔等依賴，所以建置輸出從專案根目錄改到新的 `release/` 資料夾（使用者要求）。這張票與虛擬螢幕無關，可以先做。

**Blocked by:** 無

**Status:** ready-for-agent

- [x] 切換條件分頁多一欄「強制」（核取方塊，預設不勾），cfg 的 `[Switch.N]` 以 `Forced=1|0` 儲存並有註解；舊 cfg 沒有這個欄位時當成 0
- [x] 自動切換關閉時，只檢查有勾強制的切換條件；檢查順序仍照編號
- [x] 設定視窗開著時，有勾強制的切換條件照樣生效，沒勾的照舊暫停；切換後設定視窗維持開啟，編輯中的副本不受影響（目前模式以協調者為準，見 `ApplySettings`）
- [x] 鉤子需求跟著調整：會被檢查的條件中有「偵測到使用＋鍵盤滑鼠」時才安裝鉤子

- [x] 刪除專案根目錄的舊 exe；開機啟動在新 exe 第一次啟動時會改寫成新路徑（`SyncStartup`），手動實測確認
- [x] 文件與說明中提到 exe、cfg 位置的地方都改成 `release/`

## Comments

### 2026-11-21 實作完成（待手動實測）

#### 強制（核心）

- `SwitchCondition` 新增 `Forced`（預設 false）。`Describe` 有勾強制時結尾加上「（強制）」，所以狀態摘要（啟動、重新載入的通知）與 cfg 裡每條切換條件上方的註解都看得出來。
- 協調者新增 `ConditionsToCheck()`：來源模式等於目前模式，且「自動切換開啟、設定視窗沒開」或「這條有勾強制」。`Tick` 與 `ApplyHookPolicy` 都改用它，兩邊的判斷不會分歧。
  - `Tick` 不再因為自動切換關閉或設定視窗開著就提早返回，只剩切換中與緩衝期（啟動、切換後、失敗後、開關自動切換、關閉設定視窗）會擋下。強制條件也遵守這些緩衝期。
  - 鉤子：沒有在切換，而且會被檢查的條件中有「偵測到使用＋鍵盤滑鼠」才安裝。自動切換關閉或設定視窗開著時，只看有勾強制的條件。
- 設定視窗開著時依強制條件切換：`OnSwitchFinished` 只改協調者的設定，設定視窗的副本不受影響。套用時目前模式本來就以協調者為準（`ApplySettings`），擷取也會因為 `captureStale` 而失效，所以不必另外處理。
- 依強制條件切換不會改變自動切換的開關（`ManualAutoSwitch` 只用在手動切換）。

#### cfg

- `[Switch.N]` 新增 `Forced=1|0`，一律寫出。讀取時沒寫就當成 0，所以舊 cfg 照常讀取，下次存檔時補上 `Forced=0`。
- 切換條件段落的註解：檢查規則補上「自動切換關閉或設定視窗開著時，只檢查 Forced=1 的切換條件」，欄位說明與範例也加上 `Forced`。

#### 設定視窗

- 切換條件分頁最後多一欄「強制」（核取方塊，標題有提示文字）。
- 欄寬：「鍵盤滑鼠」「聲音」都改成 `FillWeight` 62。加了一欄之後「閒置時間」被擠到換行，所以從 60 調到 70，「強制」是 45。在 150% 下實際寬度是：鍵盤滑鼠 90、聲音 90、閒置時間 102、強制 65 像素，標題都在同一行。
- 未套用的變更：底部改成三欄（說明｜提醒｜確定、取消、套用）。`SetPending` 讓「套用」按鈕和「有尚未套用的變更」一起切換，套用成功後一起消失。
- 關閉前確認：`OnFormClosing` 在 `CloseReason.UserClosing` 而且有未套用的變更時，詢問「要放棄尚未套用的變更嗎？」，預設按鈕是「否」，選否就取消關閉。「取消」、✕、Esc 都會走到這裡。
  - 「確定」會先套用，成功後已經沒有未套用的變更，所以不會跳出確認。
  - 從右鍵選單結束程式時改呼叫 `CloseDiscardingChanges()`，直接放棄、不確認。Windows 關機時 `CloseReason` 不是 `UserClosing`，也不會確認。
- 說明：切換條件分頁的說明、分頁下方的提示、右鍵選單的說明都補上強制的意思；「設定視窗開著時暫停自動切換」改寫成「暫停沒勾強制的切換條件」。

#### 建置輸出改到 release/

- `build.bat` 把 exe 複製到 `release/AutoDisplayMode.exe`。驅動的 `x64/`、`AutoDisplayMode-SudoVDA.cer`、`LICENSE.txt` 複製到 `release/drivers/sudovda/`：每次先刪掉舊的 `release/drivers` 再複製，`drivers/sudovda/` 刪掉的檔案就不會殘留。`README.md` 與 `build-driver.ps1` 是給開發者看的，不複製。
- 舊的輸出位置：`build.bat` 最後會試著刪除專案根目錄的 `AutoDisplayMode.exe`；舊版程式還在執行、刪不掉時，只印出提示，建置不算失敗。
- `git mv AutoDisplayMode.cfg release/AutoDisplayMode.cfg`。`.gitignore` 改成 `/release/*` 加上 `!/release/AutoDisplayMode.cfg`，根目錄的 `/AutoDisplayMode.exe` 仍然忽略。
- 文件：`Program.cs` 開頭的建置說明，以及 `drivers/sudovda/README.md`（說明 build.bat 會複製到哪裡；開頭的「遠端模式」順便改成「潛行模式」）。右鍵選單說明裡的 cfg 位置是執行時才取得的路徑，不必修改。
- 根目錄的舊 exe 還沒刪：實作時舊版程式正在執行，exe 被鎖住。關閉舊版程式後再執行一次 `build.bat` 就會刪除（見手動實測步驟 1）。

#### 檢查

- `build.bat`：建置 0 警告、0 錯誤，測試 230 個全部通過（新增 16 個，在 `ForcedConditionTests`）。`release/` 裡有 exe、cfg、`drivers/sudovda/`（`.cat` 與正本逐位元相同），`git status` 只看得到 cfg 的搬移。
- 新增的測試：
  - 自動切換關閉時只檢查強制條件、檢查順序照編號、強制的偵測到使用、從右鍵選單關閉後照樣生效、遵守啟動緩衝期。
  - 設定視窗開著時：只有強制條件生效、切換後視窗維持開啟、副本不受影響、套用時目前模式以協調者為準。
  - 鉤子需求：自動切換關閉、設定視窗開著、強制條件只有閒置或只選聲音時不安裝、開關自動切換。
  - 新增的切換條件預設不勾強制；狀態摘要標示強制。
  - cfg round-trip：手寫 cfg 一條有 `Forced=1`、一條沒寫，讀成 true／false，寫出 `Forced=1`／`Forced=0`，再讀回結果相同。
- 以拋棄式小程式（假的轉接層＋真正的 cfg 內容）在 150% 下開啟真正的設定視窗，自動操作並截圖：
  - 剛開啟時沒有提醒。勾選一條的「強制」後，「說明」右邊出現紅字「有尚未套用的變更」。
  - 按「取消」跳出確認，回答「否」後視窗仍然開著；按「套用」後提醒消失、「套用」變灰，協調者的設定也有強制。
  - 沒有未套用的變更時按「取消」，直接關閉、不跳確認。
  - ✕ 和 Esc 走同一段程式（`OnFormClosing`），沒有另外自動測試。

#### 手動實測步驟

1. 從工作列關閉正在執行的舊版程式（專案根目錄的 exe），執行 `build.bat`：最後印出 `Build OK: …\release\AutoDisplayMode.exe`，沒有「could not delete the old …」的提示，專案根目錄的 `AutoDisplayMode.exe` 已經刪除。`release/drivers/sudovda/` 裡有 `x64/`（3 個檔案）、`.cer`、`LICENSE.txt`。
2. 啟動 `release/AutoDisplayMode.exe`：啟動通知正常，模式與切換條件跟原本一樣（cfg 已經搬到 `release/`）。右鍵選單「說明」的 cfg 位置是 `release\AutoDisplayMode.cfg`。
3. 開機啟動（cfg 裡 `StartWithWindows=1` 時）：開啟登錄編輯程式，`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中本程式的值已經是 `release\AutoDisplayMode.exe` 的路徑。
4. 設定視窗的切換條件分頁：最後一欄是「強制」，預設不勾；「鍵盤滑鼠」與「聲音」等寬；欄位標題都沒有換行；分頁下方的提示與「說明」都有寫到強制。
5. 修改任一個欄位：「說明」右邊出現「有尚未套用的變更」。分別按「取消」、✕、Esc：都會問「要放棄尚未套用的變更嗎？」，選「否」留在視窗；選「是」關閉，下次開啟時修改不見。
6. 修改後按「套用」：提醒消失。再按「取消」直接關閉，不會詢問。修改後按「確定」也直接關閉，修改有存進 cfg。
7. 強制＋自動切換關閉：替目前模式加一條「偵測到使用（鍵盤滑鼠）」並勾強制，再加一條不強制的閒置 1 分鐘條件，然後套用並關閉設定視窗。從右鍵選單關閉自動切換（圖示變空心），放著不動超過 1 分鐘不會切換；動一下滑鼠就切換到強制條件的目標模式，自動切換仍是關閉。
8. 強制＋設定視窗開著：回到有強制條件的模式，開啟設定視窗並在某個分頁改一個值（先不要套用）。動一下滑鼠，切換到目標模式，設定視窗維持開啟，提醒仍在。按「套用」後目前模式維持切換後的模式，剛才的修改也有存進去。
9. 用記事本開啟 cfg：`[Switch.N]` 都有 `Forced=0` 或 `Forced=1`，切換條件段落的註解有說明 `Forced`，有勾強制的那條上方註解結尾是「（強制）」。
10. 實測完把第 7、8 步加的切換條件刪掉（或保留需要的），恢復自動切換。
