# 03: 潛行模式、內建切換條件與復原模式

**What to build:** 新增潛行模式（使用者故事 1～20、30、33），以及復原模式的記錄、程式啟動時的復原（28），和虛擬螢幕意外消失時的處理（29）。核心新增「虛擬螢幕」介面，Windows 轉接層以 SudoVDA 的 IOCTL 實作（做法依票 02 的結果）；偵測螢幕時排除本程式建立的虛擬螢幕。驅動的安裝與移除已在票 02 完成。

**Blocked by:** 01, 02

**Status:** ready-for-agent

- [ ] 模式分頁有「新增潛行模式（虛擬螢幕）」；複製潛行模式得到潛行模式；一般模式和潛行模式不能互相轉換；清單上看得出哪些是潛行模式
- [ ] 潛行模式的設定：名稱、圖示顏色、手動切換進入時的自動切換、虛擬螢幕解析度與更新率（下拉選單，預設 1920×1080@60）；不顯示「未記錄的螢幕」。下拉選單從驅動實際提供的模式中挑常見的（3840×2160、2560×1440、1920×1080、1366×768、1280×720 等），更新率依解析度列出（見票 02 的 Answer）
- [ ] 螢幕配置分頁選到潛行模式時，不顯示畫布，改顯示說明
- [ ] 「以目前螢幕狀態覆蓋此模式」對潛行模式停用；「以目前螢幕狀態新增模式」一律建立一般模式；處於潛行模式時，右鍵選單和分頁中的擷取都停用並說明原因
- [ ] 最後一個一般模式不能刪除
- [ ] 每個潛行模式剛好一條內建切換條件：新建時加在清單最後、不能刪除、可以拖動；條件、使用來源、強制都鎖定，只能選目標（只能選一般模式）；潛行模式刪除時一起刪除
- [ ] 內建切換條件的目標失效時，改成順序第一個一般模式，並在套用時提示
- [ ] 內建切換條件一律只認實體鍵盤滑鼠，不受「忽略遠端連線軟體送出的鍵盤滑鼠輸入」影響
- [ ] 進入潛行模式時，先建立虛擬螢幕再關閉所有螢幕；離開時，先開啟螢幕再移除虛擬螢幕；潛行模式之間切換時，只換解析度
- [ ] 進入潛行模式時，等的是虛擬螢幕**存在**，不是它被開啟：Windows 可能一建立就依記憶套用上次的配置（已經只開虛擬螢幕，或讓虛擬螢幕維持關閉），兩種情況都明確套用「只開虛擬螢幕」
- [ ] 只在進入潛行模式時建立虛擬螢幕，其他時候都不建立（Windows 可能依記憶直接關掉實體螢幕）
- [ ] 更新率比對時把 59 和 60 視為相同：指定 60 Hz 建立會得到 59.94 Hz（GDI 回報 59），不要因此判定失敗或一直重新套用
- [ ] 驅動不可用或建立失敗時，拒絕切換並通知，維持原本的模式
- [ ] 驅動不可用時，模式分頁中潛行模式旁顯示警告與「安裝驅動」按鈕（原票 05，使用者故事 34）
- [ ] 處於潛行模式時，從介面執行緒持續送心跳（每秒一次就夠），一直送到虛擬螢幕移除為止，離開潛行模式、套用一般模式的期間也要送；不在套用螢幕設定的執行緒送（`SetDisplayConfig` 可能花 1～2 秒）。移除時驅動回報找不到，就當成已經被移除
- [ ] 協調者記錄復原模式（切換到一般模式時更新，重新編號時跟著改）；程式啟動時若目前模式是潛行模式，就改套用復原模式；復原模式不存在時，使用備案
- [ ] 虛擬螢幕意外消失時，切回復原模式並通知
- [ ] 偵測、擷取、套用、畫布都排除本程式建立的虛擬螢幕，其他虛擬顯示照舊。以介面卡的硬體 ID `Root\SudoMaker\SudoVDA` 辨識，不用目標 ID（每次建立都會變）
- [ ] cfg：`RestoreMode`、`Kind`、`VirtualWidth`／`VirtualHeight`／`VirtualRefreshRate`、`BuiltIn`，加上註解；讀取時驗證內建切換條件，不符就修正並提示
- [ ] 各分頁的說明與右鍵選單的說明，補上潛行模式、內建切換條件與復原模式；潛行模式的說明要寫出效果與用途（使用者故事 8a）：遠端連線、省下螢幕的電與部分顯示卡負擔（不及睡眠），以及「潛行」不是防窺
- [ ] 測試：spec Testing Decisions 中與潛行模式、內建切換條件、復原模式、cfg 相關的行為
- [ ] 手動實測：用 Chrome 遠端桌面實際連線，進入潛行模式、在電腦前動滑鼠回到一般模式、潛行模式之間切換、拒絕切換；用比例跟電腦不同的裝置（例如手機）連線，記錄「調整桌面大小以符合」的行為（票 02 用筆電測，解析度沒變，沒有結論）

## Comments

### 2026-11-22 依票 02 的實測結果修改

- 票 02 的精靈實測沒有推翻 spec 的假設：驅動能用程式的介面安裝與移除；一般使用者權限就能建立虛擬螢幕；心跳停止後 3.4～3.9 秒內移除；Chrome 遠端桌面看得到只剩虛擬螢幕的畫面，送來的輸入全部帶注入旗標；睡眠喚醒後虛擬螢幕還在。詳見票 02 的 Answer。
- 新發現：Windows 的顯示資料庫會依「接上了哪些螢幕」記住上一次的配置（`SDC_SAVE_TO_DATABASE`），包括含虛擬螢幕的組合。所以虛擬螢幕一建立，Windows 就可能自己改配置。
- 依此修改的驗收項目：
  - 解析度下拉選單：從驅動實際提供的模式中挑選。
  - 進入潛行模式：等虛擬螢幕存在就好，不論 Windows 有沒有開啟它，都明確套用「只開虛擬螢幕」。
  - 只在進入潛行模式時建立虛擬螢幕（新增一項）。
  - 更新率 59／60 視為相同（新增一項）。
  - 心跳：送到虛擬螢幕移除為止，移除時「找不到」當成已移除。
  - 偵測：以介面卡的硬體 ID 排除虛擬螢幕。
  - 手動實測：用手機再看一次「調整桌面大小以符合」。
