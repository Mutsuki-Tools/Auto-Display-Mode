# 04: 分層復原，以及目標模式「回到上個配置」

**Blocked by:** 03

**Status:** ready-for-agent

這張票有兩個互不相依的部分，可以分開做、分開提交：

- **第一部分：分層復原**（ADR-0006，使用者故事 24～27）：處於潛行模式時，不論程式怎麼結束，都要當下切回復原模式。
- **第二部分：「回到上個配置」**（使用者提出）：切換條件的目標模式可以選「回到上個配置」，切回進入目前模式之前所在的模式。

## 開工前要知道（票 02、03 的結果）

**已經做好的（票 03）**

- 協調者的 `Start()` 會移除上次留下的虛擬螢幕，目前模式是潛行模式時改套用復原模式。斷電後重開機的復原已經完成。
- 虛擬螢幕意外消失時，會切回復原模式並通知。
- 離開潛行模式的順序（守護程式可以沿用）：
  1. 依一般模式開啟螢幕（虛擬螢幕還在）。
  2. 移除虛擬螢幕。
  3. 等 1.5 秒（`AppCoordinator.SettleMs`）。
  4. 重新套用一次。
- `TrayApp.ExitApp` 目前只停止心跳，還沒先切回復原模式。

**心跳**

- SetDisplayConfig 開關實體螢幕時，介面執行緒會卡住 2.5～2.8 秒，超過驅動的 3 秒逾時。
- 所以 `SudoVdaVirtualDisplay` 另有心跳執行緒，每 0.5 秒補送，但只在介面執行緒 5 秒內呼叫過 `Ping` 時才補。介面真的卡死時，最多約 8 秒虛擬螢幕才會消失。
- 守護程式判斷「心跳逾時」時，也要容許介面短暫卡住幾秒。

**Windows 自己的還原（票 02 實測，只驗證過單螢幕）**

- 只剩虛擬螢幕時強制結束程式：3.4 秒後驅動移除虛擬螢幕，再過約 0.4 秒，Windows 以它記住的「只有實體螢幕」配置點亮螢幕，沒有黑畫面。
- Windows 還原的是實體螢幕單獨接著時最後存下的配置（現有程式套用時用 `SDC_SAVE_TO_DATABASE`），通常就是復原模式。但多螢幕沒有驗證過，而且 cfg 的目前模式需要有人更新，所以守護程式仍然需要。

**其他**

- 「調整桌面大小以符合」：用手機連線時沒有任何改變，使用者決定不需要。虛擬螢幕的解析度照模式的靜態設定，本票不必處理。

## 第一部分：分層復原

### 程式自己結束時

- [ ] 從右鍵選單結束程式時，若處於潛行模式，先套用復原模式（等它完成）再結束
- [ ] 收到 `WM_QUERYENDSESSION`／`WM_ENDSESSION`（關機、登出、重開機）時，若處於潛行模式，先套用復原模式

### 守護程式

- [ ] 用同一個 exe 加參數啟動，不放進主程式的 job object；進入潛行模式時啟動，經由切換離開潛行模式時結束
- [ ] 監看主程式的存活與心跳（逾時要容許介面卡住幾秒，見上方「心跳」）
- [ ] 主程式不是正常結束或心跳逾時時，依序：
  1. 讀取 cfg。
  2. 移除虛擬螢幕（若還在）。
  3. 等 Windows 自己的還原結束（約 0.4 秒；可以等螢幕配置不再變化），避免和 Windows 同時改配置。
  4. 套用復原模式。
  5. 更新 cfg 的目前模式，然後結束。
- [ ] 主程式正常結束時通知守護程式，不會重複套用
- [ ] 守護程式套用後，主程式若從卡住中恢復，不會又切回潛行模式（依票 03「虛擬螢幕意外消失」的處理，以及 cfg 的目前模式）
- [ ] 只能有一個守護程式；主程式重新啟動時，若守護程式還在，要能正確接手或結束它

### 測試與實測

- [ ] 測試：核心中能測的部分（例如結束前的復原、守護程式的決策邏輯，若有抽出）
- [ ] 手動實測，每種都要在幾秒內回到復原模式：
  - 用工作管理員結束主程式
  - 讓主程式卡住（例如以除錯器暫停）
  - 登出
  - 重開機
- [ ] 手動實測：結束守護程式本身時，由驅動的心跳保險與 Windows 接手
- [ ] 手動實測要包括平常使用的多螢幕一般模式：主程式與守護程式都被強制結束後，記錄 Windows 自己還原成什麼樣子

## 第二部分：目標模式「回到上個配置」

### 已決定的事

- **意思是「上一個模式」**：進入目前模式之前所在的模式，一般模式與潛行模式都算。它不是復原模式（復原模式只算一般模式）。
- **名稱**：介面上的選項叫「回到上個配置」（使用者決定：直白、沒有專有名詞）。GLOSSARY 把「配置」列為「模式」要避免的說法，所以「配置」只用在這個選項的文字，程式、cfg、說明的內文都稱為「上一個模式」。
- **什麼時候更新**：每次切換到**不同的**模式完成時，原本的目前模式成為上一個模式，包括手動切換、切換條件與切回復原模式；重新套用同一個模式不算。存進 cfg，重新啟動後仍記得。
- **實際目標在切換時才決定**：
  - 上一個模式不存在（被刪除、還沒切換過）時，用順序第一個一般模式。
  - 內建切換條件的作用是讓坐在電腦前的人回到實體螢幕，所以上一個模式是潛行模式時（例如從一個潛行模式切到另一個），改用復原模式。
  - 規劃被拒絕時比照票 03：離開潛行模式時開啟所有接上的螢幕，其他情況拒絕切換。
- **內建切換條件的預設目標**：新建或複製潛行模式時，預設改成「回到上個配置」（使用者決定，取代使用者故事 15 的「順序第一個一般模式」）。已經存在的不自動改。
- **不會失效**：cfg 寫成 `To=Previous`，不指向模式編號，重新編號與刪除模式都不影響它。內建切換條件「目標失效時改成第一個一般模式」的規則照舊，但不會發生在這個選項上。

### 要做的事

- [ ] 切換條件分頁的目標模式下拉選單多一個「回到上個配置」（排在模式之前），任何來源模式都能選，內建切換條件也能選；意思寫在儲存格的提示與說明中
- [ ] 新建或複製潛行模式時，內建切換條件的預設目標是「回到上個配置」
- [ ] 協調者記錄上一個模式，存進 cfg 的 `[General] PreviousMode`，重新編號時跟著改
- [ ] 切換時依上方規則決定實際目標
- [ ] cfg：`To=Previous`，並加上註解
- [ ] 狀態摘要、說明與右鍵選單的說明寫出「→ 回到上個配置」
- [ ] GLOSSARY 新增「上一個模式」，並說明介面上的選項名稱
- [ ] 測試：
  - 一般模式與潛行模式來源都能切回上一個模式
  - 上一個模式不存在時的備案
  - 內建切換條件遇到上一個模式是潛行模式時，改用復原模式
  - 重新編號
  - cfg round-trip
