# 04: 分層復原（結束、關機登出、守護程式）

**What to build:** 依 ADR-0006，處於潛行模式時，不論怎麼離開都要當下切回復原模式（使用者故事 24～27）。程式自行結束，以及收到工作階段即將結束的通知時，先套用復原模式。進入潛行模式時啟動守護程式；主程式閃退、被強制結束或心跳逾時，就由守護程式套用復原模式。斷電後的啟動復原、虛擬螢幕意外消失的處理，已在票 03 完成。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 從右鍵選單結束程式時，若處於潛行模式，先套用復原模式（等它完成）再結束
- [ ] 收到 `WM_QUERYENDSESSION`／`WM_ENDSESSION`（關機、登出、重開機）時，若處於潛行模式，先套用復原模式
- [ ] 守護程式：建議用同一個 exe 加參數啟動，不放進主程式的 job object；進入潛行模式時啟動，經由切換離開潛行模式時結束
- [ ] 守護程式監看主程式的存活與心跳；主程式不是正常結束或心跳逾時（數秒），就讀取 cfg、移除虛擬螢幕（若還在）、套用復原模式、更新 cfg 的目前模式，然後結束
- [ ] 守護程式移除虛擬螢幕後，先等 Windows 自己的還原結束（票 02 實測約 0.4 秒；可以等螢幕配置不再變化）再套用復原模式，避免和 Windows 同時改配置
- [ ] 主程式正常結束時通知守護程式，不會重複套用
- [ ] 守護程式套用後，主程式若從卡住中恢復，不會又切回潛行模式（依票 03「虛擬螢幕意外消失」的處理，以及 cfg 的目前模式）
- [ ] 只能有一個守護程式；主程式重新啟動時，若守護程式還在，要能正確接手或結束它
- [ ] 測試：核心中能測的部分（例如結束前的復原、守護程式的決策邏輯，若有抽出）
- [ ] 手動實測：用工作管理員結束主程式、讓主程式卡住（例如以除錯器暫停）、登出、重開機，每種都在幾秒內回到復原模式；結束守護程式本身時，由驅動的心跳保險與 Windows 接手
- [ ] 手動實測要包括平常使用的多螢幕一般模式：主程式與守護程式都被強制結束後，記錄 Windows 自己還原成什麼樣子（票 02 只驗證過單螢幕）

## Comments

### 2026-11-22 依票 02 的實測結果修改

- 票 02 驗證了 ADR-0006 的第 3 層（單螢幕）：只剩虛擬螢幕時強制結束測試工具，3.4 秒後驅動的心跳保險移除虛擬螢幕，再過約 0.4 秒，Windows 就以它記住的「只有實體螢幕」配置點亮螢幕，沒有黑畫面、不必按 Win+P。詳見票 02 的 Answer。
- Windows 還原的是實體螢幕單獨接著時最後存下的配置（現有程式套用時用 `SDC_SAVE_TO_DATABASE`），通常就是復原模式。守護程式仍然需要：多螢幕的情況沒有驗證，而且要更新 cfg 的目前模式。
- 依此新增兩項：
  - 守護程式移除虛擬螢幕後，等 Windows 自己還原完，再套用復原模式。
  - 手動實測包括多螢幕的一般模式。
- ADR-0006 與這次結果一致，不必修改。
