# 潛行模式與虛擬螢幕

Status: ready-for-agent

## Problem Statement

使用者常用 Chrome 遠端桌面從外面連回這台電腦。Chrome 遠端桌面擷取的是桌面上開著的螢幕，所以遠端時實體螢幕必須開著：既浪費電，遠端畫面也被實體螢幕的數量、排列與解析度綁住，視窗還可能開在遠端不方便看的螢幕上。使用者想要一種模式：關閉所有螢幕，只留一個解析度可自選的虛擬螢幕給遠端使用。風險在於所有螢幕都關閉時，只要程式閃退、被強制結束、被作業系統關閉或斷電，坐在電腦前的人就可能看不到任何畫面，所以任何意外都必須自動回到有實體螢幕的狀態。

## Solution

- 新增一種模式：**潛行模式**。所有螢幕關閉，只開啟本程式建立的**虛擬螢幕**，解析度與更新率可在模式中選擇。潛行模式和**一般模式**一樣，可以有多個、可以手動切換，也能當切換條件的來源模式與目標模式。
- 潛行模式只能用「新增潛行模式」建立，或複製既有的潛行模式；一般模式和潛行模式不能互相轉換。
- 每個潛行模式自帶一條**內建切換條件**：偵測到使用（鍵盤滑鼠，只認實體輸入）時，切換到所選的一般模式。這條不能刪除，而且一律**強制**。人回到電腦前一動滑鼠，就會換回實體螢幕。
- 切換條件新增「強制」欄位：勾選後，即使自動切換關閉、設定視窗開著，這條也照樣生效。
- 離開潛行模式若不是經由切換（程式結束、閃退、斷電、虛擬螢幕意外消失），一律回到**復原模式**，也就是最後一個處於過的一般模式。復原以分層機制完成（ADR-0006）。
- 虛擬螢幕驅動由本程式內附：自行編譯並自簽的 SudoVDA（ADR-0005），從設定視窗安裝與移除，不依賴 Parsec 等其他軟體。
- 順帶改進設定視窗：「鍵盤滑鼠」與「聲音」兩欄等寬；有尚未套用的變更時顯示提醒，關閉時也會先確認。

## User Stories

### 潛行模式

1. 作為使用者，我想用「新增潛行模式」建立一個潛行模式，以便遠端時關閉所有螢幕、只給遠端一個畫面。
2. 作為使用者，我想建立多個潛行模式（例如「潛行 4K」「潛行筆電」），以便針對不同的用戶端裝置使用不同的解析度。
3. 作為使用者，我想複製一個潛行模式，得到另一個潛行模式，以便只改解析度就有新的潛行模式。
4. 作為使用者，我希望一般模式不能改成潛行模式、潛行模式也不能改成一般模式，以便兩種模式的設定不會互相混雜。
5. 作為使用者，我想從下拉選單選擇潛行模式的虛擬螢幕解析度與更新率（常見解析度，預設 1920×1080@60），以便配合用戶端的螢幕。
6. 作為使用者，我希望遠端期間 Chrome 遠端桌面調整了解析度，程式不會改回來，也不會存進模式，以便遠端時可以臨時調整。
7. 作為使用者，我想像一般模式一樣替潛行模式設定名稱、圖示顏色與「手動切換進入時的自動切換」，以便操作方式一致。
8. 作為使用者，我希望在模式清單中一眼分辨哪些是潛行模式（標示「（潛行）」），新增按鈕寫成「新增潛行模式（虛擬螢幕）」，以便不會選錯。
8a. 作為使用者，我希望說明清楚寫出潛行模式的效果與用途：所有螢幕關閉、電腦照常運作、只剩虛擬螢幕給遠端連線軟體擷取；也能省下螢幕的電與部分顯示卡負擔（省電效果不及睡眠，它是為了同時支援遠端）；「潛行」不是防窺，一動實體鍵盤滑鼠就會離開，以便沒聽過虛擬螢幕的人也看得懂。
9. 作為使用者，我希望潛行模式不顯示「未記錄的螢幕」設定，螢幕配置分頁也不顯示畫布，改說明潛行模式的螢幕一律關閉，以便不必設定沒有意義的東西。
10. 作為使用者，我希望處於潛行模式時無法擷取（選單項目變灰色並說明原因），以便不會把「全部關閉」存進一般模式。
11. 作為使用者，我希望「以目前螢幕狀態覆蓋此模式」對潛行模式停用，「以目前螢幕狀態新增模式」一律建立一般模式。
12. 作為使用者，我希望至少保留一個一般模式（最後一個一般模式不能刪除），以便內建切換條件與復原模式永遠有地方可回。
13. 作為使用者，我希望潛行模式之間也能直接切換，例如從「潛行 4K」切到「潛行筆電」只改變虛擬螢幕的解析度。

### 內建切換條件與強制

14. 作為使用者，我希望每個潛行模式自動帶一條「偵測到使用（鍵盤滑鼠）→ 一般模式」的內建切換條件，以便回到電腦前一動滑鼠鍵盤，就換回實體螢幕。
15. 作為使用者，我想選擇內建切換條件的目標模式（只能選一般模式，預設是順序第一個一般模式），其他欄位都鎖定。
16. 作為使用者，我希望內建切換條件不能刪除，以便不會不小心把自己鎖在全黑的螢幕外。
17. 作為使用者，我希望內建切換條件只認實體鍵盤滑鼠，不管「忽略遠端連線軟體送出的鍵盤滑鼠輸入」是否勾選，以便我在 Chrome 裡操作時不會被踢出潛行模式。
18. 作為使用者，我想拖動內建切換條件，調整它和其他切換條件的順序，跟一般的切換條件一樣。
19. 作為使用者，我希望新建潛行模式時，它的內建切換條件加在清單最後；刪除潛行模式時，它的內建切換條件一起刪除。
20. 作為使用者，我希望內建切換條件的目標模式被刪除時，目標自動改成順序第一個一般模式，並在套用時提示。
21. 作為使用者，我想在任何切換條件勾選「強制」（預設不勾），讓它在自動切換關閉時也照樣生效。
22. 作為使用者，我希望有勾強制的切換條件在設定視窗開著時也照樣生效，切換後設定視窗維持開啟、編輯中的內容不受影響。
23. 作為使用者，我希望內建切換條件的強制欄位一律勾選、不能改。

### 復原

24. 作為使用者，我希望從右鍵選單結束程式時，先切回復原模式再結束。
25. 作為使用者，我希望關機、登出、重開機（含 Windows 更新）時，程式先切回復原模式。
26. 作為使用者，我希望程式閃退或被工作管理員結束時，幾秒內自動切回復原模式，不必等程式重新啟動。
27. 作為使用者，我希望程式卡住時，也會在幾秒內切回復原模式。
28. 作為使用者，我希望斷電重開機後，程式啟動時若目前模式是潛行模式，就改套用復原模式，不會又自動進入潛行模式。
29. 作為使用者，我希望程式還在執行、但虛擬螢幕被系統移除時（睡眠喚醒、顯示卡驅動重置），程式切回復原模式並通知我，不自動重建虛擬螢幕。
30. 作為使用者，我希望復原模式被刪除時改用順序第一個一般模式；再沒有一般模式時，開啟所有接上的螢幕。

### 驅動

31. 作為使用者，我想在設定視窗按「安裝驅動」安裝虛擬螢幕驅動（需要系統管理員權限一次），以便不需要另外安裝其他軟體；把程式資料夾（exe 加上 drivers 資料夾）複製到別台電腦時，也能用同樣的方式安裝。
32. 作為使用者，我想在設定視窗按「移除驅動」移除驅動，並一併刪除安裝時匯入的根憑證。
33. 作為使用者，我希望驅動沒裝或無法建立虛擬螢幕時，切換到潛行模式會被拒絕並跳通知，留在原本的模式。
34. 作為使用者，我希望在設定視窗中看到潛行模式旁的警告與「安裝驅動」按鈕，以便知道為什麼潛行模式無法使用。

### 設定視窗

35. 作為使用者，我希望切換條件分頁的「鍵盤滑鼠」與「聲音」兩欄一樣寬。
36. 作為使用者，我希望有改過但還沒套用時，設定視窗下方（「說明」右邊）顯示「有尚未套用的變更」，套用成功後消失。
37. 作為使用者，我希望有未套用的變更時，按「取消」或右上角 ✕ 會先問「要放棄尚未套用的變更嗎？」。

## Implementation Decisions

### 名詞

依 `GLOSSARY.md`：潛行模式、一般模式、虛擬螢幕、復原模式、內建切換條件、強制。程式內的命名與介面文字都沿用這些詞，不要出現「虛擬模式」「VDD」「使用虛擬螢幕的模式」。

### 虛擬螢幕驅動（ADR-0005）

- 內附 SudoVDA：從原始碼編譯，用拋棄式自簽憑證簽章，簽完刪除私鑰。repo 只放簽好的驅動檔與公開憑證。
- 控制方式是 IOCTL：以 SetupDi 找裝置介面，再用 CreateFile、DeviceIoControl 操作。介面有新增虛擬螢幕（帶寬、高、更新率）、移除、心跳（ping）。執行時不需要系統管理員權限。
- 驅動端的心跳保險：超過逾時時間沒收到任何 IOCTL，就移除所有虛擬螢幕；預設 3 秒，維持預設值。心跳從主程式的介面執行緒送出，所以介面卡住時心跳也會停。
- 安裝與移除以提權的子程序執行：匯入憑證到「受信任的根憑證」與「受信任的發行者」，再建立裝置節點並安裝 INF。
- 可攜性：建置輸出到 `release/`，驅動檔與公開憑證放在 exe 旁邊的 `drivers/sudovda/`，不嵌進 exe；換驅動版本或憑證時只要替換檔案。把整個 `release/` 資料夾複製到其他電腦，就能由程式自己安裝與移除驅動。安裝流程只用 Windows 內建的 API（SetupAPI、`X509Store` 等），不依賴 WDK、devcon、nefcon 等另外下載的工具，並放在獨立的介面後面，實測失敗時只要替換這個實作。

### 核心的新介面（port）

- **虛擬螢幕**：驅動是否可用、建立（寬、高、更新率）、移除、心跳、目前是否存在。虛擬螢幕意外消失時由轉接層回報。測試以假物件實作。
- 螢幕系統的偵測結果**排除本程式建立的虛擬螢幕**：它不是螢幕，不出現在偵測、擷取、套用與畫布中。電腦上其他軟體建立的虛擬顯示畫面（Meta Virtual Monitor、Wacom MovinkPad 等）照舊當螢幕看待。

### 套用潛行模式的順序

- 進入：先建立虛擬螢幕並等它出現，再關閉所有螢幕。Windows 至少要有一個開啟的畫面，順序不能反過來。
- 離開到一般模式：先依一般模式開啟螢幕，再移除虛擬螢幕。
- 潛行模式之間切換：保留虛擬螢幕，只換解析度，或移除後以新解析度重新建立。
- 建立虛擬螢幕失敗，就拒絕切換並通知，維持原本的模式。

### 切換引擎

- 自動切換關閉或設定視窗開著時，只檢查有勾強制的切換條件。檢查順序仍照編號，第一條成立的就切換。其他暫停條件不變：切換中、切換後的緩衝期、失敗後的暫停期。
- 鉤子需求要一併調整：目前模式有「偵測到使用＋鍵盤滑鼠」且會被檢查的切換條件時，就要安裝鉤子，也要考慮強制條件在自動切換關閉、設定視窗開著時的情況。
- 內建切換條件一律忽略遠端注入的輸入。同一個潛行模式裡如果還有自訂的「偵測到使用＋鍵盤滑鼠」條件，而且全域設定不忽略遠端輸入，就需要兩種鍵盤滑鼠使用訊號：全部輸入，以及只有實體輸入。

### 復原（ADR-0006）

- 協調者記錄復原模式：每次切換到一般模式就更新。套用設定重新編號時（ADR-0004）跟著改。
- 程式啟動時，如果目前模式是潛行模式，就改套用復原模式。
- 程式自行結束，以及收到 `WM_QUERYENDSESSION`／`WM_ENDSESSION` 時，先套用復原模式再結束。
- 守護程式：進入潛行模式時啟動，離開潛行模式（經由切換）時結束。它監看主程式的存活與心跳；主程式不是正常結束，或心跳逾時，就讀取 cfg、套用復原模式並更新目前模式，然後結束。建議用同一個 exe 加參數啟動，以重用核心與螢幕系統。不要放進主程式的 job object，以免工作管理員的「結束工作」一起結束它。
- 虛擬螢幕意外消失時（轉接層回報）：套用復原模式並通知。

### cfg 格式（建議）

- `[General]` 新增 `RestoreMode=N`（復原模式的模式編號）。
- `[Mode.N]` 新增 `Kind=Normal|Remote`。潛行模式另有 `VirtualWidth`、`VirtualHeight`、`VirtualRefreshRate`，沒有 `UnlistedMonitors` 與 `[Mode.N.Monitor.K]`。
- `[Switch.N]` 新增 `Forced=1|0`，以及內建切換條件的 `BuiltIn=1`。讀取時要驗證：每個潛行模式剛好一條內建切換條件，其來源模式是自己、條件固定、強制固定、目標是一般模式；不符就修正並提示。
- cfg 的註解說明新欄位。

## Testing Decisions

- 沿用唯一的測試接縫：透過協調者入口，搭配假的螢幕系統、虛擬螢幕、使用訊號、時鐘、cfg 儲存與通知。
- **要測的行為**：
  - 強制：自動切換關閉、設定視窗開著時，只有強制條件生效；鉤子需求也隨之變化。
  - 內建切換條件：潛行模式建立與刪除時跟著建立與刪除、不能刪除、只能改目標、目標失效時改指第一個一般模式、只認實體輸入、可調整順序。
  - 潛行模式：建立虛擬螢幕再關閉螢幕的順序、建立失敗就拒絕切換、潛行模式之間的切換、偵測結果排除虛擬螢幕、處於潛行模式時不能擷取、最後一個一般模式不能刪除。
  - 復原模式：切換到一般模式時更新、重新編號時跟著改、啟動時從潛行模式改套用復原模式、虛擬螢幕意外消失時切回復原模式、復原模式不存在時的備案。
  - cfg：新欄位的 round-trip、內建切換條件的驗證與修正。
- **手動實測**：驅動的編譯、簽章與安裝，Chrome 遠端桌面實際連線，守護程式（工作管理員結束主程式、讓主程式卡住），關機、登出、睡眠喚醒，斷電後重開機。

## Out of Scope

- 自動偵測遠端連線並自動進入潛行模式（用切換條件或手動切換處理）。
- 虛擬螢幕與實體螢幕同時開啟、在畫布上一起擺放。
- 防窺（遠端時刻意讓在電腦前的人看不到畫面）。
- 緊急快速鍵，以及「潛行模式沒有偵測到使用條件」的警告：已由內建切換條件取代。
- 支援 Parsec、MttVDD 等其他虛擬螢幕驅動。
- Windows 遠端桌面（RDP）：它本來就有自己的虛擬畫面，不需要這個功能。

## Further Notes

- 相關決策：ADR-0004（模式編號）、ADR-0005（驅動）、ADR-0006（分層復原）。
- 待原型驗證的假設（票 02）。結果若推翻假設，要回頭修改票 03、04：
  - SudoVDA 能自行編譯、自簽，並在一般 Windows 11 上安裝（不開測試模式）。
  - 一般使用者權限就能新增和移除虛擬螢幕；心跳停止後虛擬螢幕會被移除。
  - Chrome 遠端桌面送來的鍵盤滑鼠輸入帶有注入旗標，會被判定為遠端輸入。
  - 只剩虛擬螢幕時，Chrome 遠端桌面看得到它，「調整桌面大小以符合」的行為如何。
  - 所有螢幕關閉時虛擬螢幕被移除，Windows 會怎麼還原實體螢幕。
- 使用者電腦上目前有 Parsec Virtual Display Driver（打算移除）、Meta Virtual Monitor、Wacom MovinkPad 的虛擬顯示，實測時要注意它們不受影響。
